The document checks (docs/validation/bench/doc_checks.py; C3 3-grams and C4 lists) build their corpus from EVERY JSON file under research/ and captures/ at run time. While the Dwellings capture lane was writing captures/dwellings/ (2026-09-26 evening), the consistency pass's repair-scope-r3 seat saw the whole-document C3 count move from 495/1 to 517/25 between two runs with the document unchanged — the new "hits" were draw-record label texts from the fresh captures, not copied text.

**Why:** an assembler or verifier that runs doc checks while another lane adds captures will see phantom unreviewed hits and may add needless allow rows or fail its exit-0 gate.

**How to apply:** when a capture lane and a document lane run at the same time, have the document lane review only the hits of its own run and compare before/after copies against ONE corpus snapshot (the r3 seat's method), or run doc checks when captures are quiescent; consider giving doc_checks.py a `--corpus-snapshot` option. See [[generation-profiler-hazards]], [[maps-project-state]].

**Method that worked (2026-09-27, amendments-b/amend-scope; findings files grow the corpus too — `research/findings/code-*.md` landed twice during one lane):**
1. Run the checks on THREE copies with the same `--sections` keys: the untouched document, the document with your blocks alone, and the combined copy (every block file in name order). Your responsibility is `mine − untouched`; `combined − mine` is other seats' text.
2. Reword your own hits (a few rounds halve them). Section-pointer digit runs are broken by words between pointers (`§2.6 beside §2.8's record`, never `§2.6, §2.8, §2.9`); a file path of five or more tokens always hits — name the file without its extension or point to its folder.
3. Hand any residue to the assembler as reviewed allow rows (check, exact hit text, reason), never as unreviewed.
4. Read the summary lines (`grep '^C3:'`), not `tail`: the summary sits before the hit list, and the first run of that lane was misread as 8 hits when the file held 102.
5. Tools: `scratchpad/peh/apply.py` (any session under `/private/tmp/claude-502/-Users-cstokes-Desktop-Maps/…/scratchpad/`) implements the block protocol exactly; the resolver `docs/validation/consistency/assemble-r0-refs.py <doc> <out.json>` needs both arguments and rejects dotted `J-A<item>.<n>` ids by grammar (widen `J-[A-Z0-9-]+?` to `J-[A-Z0-9.-]+?` and the citation regex with `(?:\.\d+)?`).
6. (2026-09-27, handfix-b/repair-rendering-r2 Fable continuation) The `doc=` header's `colour_files` count (C2's census of every text/JSON file under research/, captures/, docs/confidence, docs/improvements …) drifts by itself whenever any lane writes a file there — 10095 → 10096 between runs while `json_files`, `c3_corpus_3grams` and `c4_lists` held still. Compare headers WITHOUT `colour_files`, and judge C2 by its hit count (0 in every run), never by the census.
7. Launch the copies together so they read one snapshot: in zsh/bash `cmd > out; echo "exit $?" >> exits &` backgrounds only the `echo` — group as `( cmd > out 2>&1; echo "x exit $?" >> exits ) &` per copy, then `wait`. Six `--sections 8` runs took 3.5 min in parallel on the 8-core machine against ~3 min EACH sequentially; run the untouched copy once more after `wait` to bracket the corpus.
8. (2026-09-27, handfix-b/close) Two driver hazards: in zsh an UNQUOTED variable holding a command string (`DC="python3 path"; $DC --doc …`) is not word-split, so every parallel run exits 127 (command not found) and the batch looks finished in seconds — define the check as a shell function (`dc() { python3 docs/validation/bench/doc_checks.py "$@"; }`) or use `${=DC}`; and the hit lines have TWO formats, `UNREVIEWED C1 | README.md | l. 294` and `UNREVIEWED C3 | <run> | section from l. 6384`, so a normaliser that strips only `| l. N` reports every hit after the first changed line as added AND removed (345/345 on a clean copy) — strip `| (section from )?l. N` before comparing.
9. (2026-09-28, amendments-c/amend-pipeline-bentcut) C3's corpus includes `research/findings/code-impact.md`, which carries the 27c amendment editor texts, so a block that applies an editor text VERBATIM hits on almost every clause (58 unreviewed in one §4.6 REPLACE). Reword per clause with a pickled-corpus helper (build C3's `shared` set once, pickle it, then test candidate sentences in a loop: a run is ≥ 3 consecutive shared 3-grams). Unavoidable residue: build names — any "NG 1.2.2's", "NG 1.2.2 and", "MFCG 12710731 and VG 1.6.9" hits — and Fable's released wordings; these go to the assembler as allow rows (gate (b) requires the names).
10. (2026-09-28, amendments-c/assemble-r0) The resolver's J grammar (`amendments-b/refs.py`) is upper-case only, so Fable review ids like `J-Fdet-1`, `J-Fredteam-1`, `J-Fpipe-2` are invisible to it: a seat that folds a Fable block's section text but not its J rows leaves a dangling id the resolver reports as 0 broken. Run a case-insensitive scan (`J-[A-Za-z]*-?[A-Za-z]*\d+(\.\d+)?` cited vs `| J-… |` row ids) after every assembly.
11. (same lane) Use `docs/validation/amendments-c/apply-blocks.py` for block assembly: its default `--order two-pass` applies every REPLACE before any APPEND / INSERT AFTER, because the literal one-pass name order erases an APPEND whose file sorts before a REPLACE of the same heading (pass c: T's §4.5 APPEND vs C's §4.5 REPLACE); it also merges a second REPLACE three-way with `git merge-file`.

(2026-09-28, amendments-c/repair-rendering-r1) Rows proposed for `research/findings/code-impact.md` (new P-ids) JOIN the C3 corpus once appended, and route-verbatim wording then hits the design's OWN canonical phrases (the build name "the FTG client of the 2026-09-25 capture", "one light per lit room": 5 new unreviewed hits). Test proposed research-side rows before handing them off: copy doc_checks.py with one extra corpus file (`glob('research/findings/*.md') + [os.environ['EXTRA_C3']]`) and compare counts with and without it on the combined copy; `timeout` does not exist on this macOS, so run long checks with run_in_background, never under `timeout`.
