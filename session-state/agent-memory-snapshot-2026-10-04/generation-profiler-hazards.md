watabou builds (Haxe/OpenFL on html-classic.itch.zone/html/<buildId>/…; build id changes per upload, record.mjs re-resolves it): mangled locals but `Var.__name__="pkg.Class"` markers survive → analyze.mjs attributes CPU time + precise-coverage call counts to classes. Enter = regenerate; URL is rewritten with seed + blueprint params after each generation; MFCG traces its own stage timings to the console. Hazard: in reload mode the main thread goes quiet while assets download — idle detection must be gated on the generator's console marker + drained network (fixed 2026-09-21; a capture whose URL was NOT rewritten is a premature stop).

FTG: generation is SERVER-side (AWS API Gateway `PUT /prod/settlements` with the full ~430 KB parameter JSON → id; `GET /settlements/<id>/layout` → gzip'd protobuf, ~593 KB raw). CPU work of generation cannot be observed; the payload, client scene build and visuals can. One temporary settlement per IP per day, re-served for 24 h (ours: "Galeiaward", created 2026-09-21 ~05:17 UTC, id f4bda786-…). Hazards: (1) the layout body is consumed as a stream into a WASM decoder, so `Network.getResponseBody` returns EMPTY — must intercept at the Fetch response stage (session.mjs does); (2) a hidden page button behind the modal has the same label as the modal's create button — click only hit-testable elements (drive.mjs clicktext does); (3) all settings sections' `<select>`s are in the DOM at once — index selects from the simple form only; (4) creating a settlement implies the site's cookie consent notice. Persistent browser profile: `profiler/.profiles/ftg`.

**How to apply:** for a new FTG capture run `node session.mjs --target ftg` then drive step by step; never automate the create click blind. See [[maps-project-state]].

FTG payload decoding hazard (found by the Fable FTG critic seat, 2026-09-25): coordinates in the protobuf layout are zig-zag `sint32` centred on (0,0), ±2500 m, `+y` north. Decoding them as unsigned varints folds the map and doubles every distance (areas ×4) — that is what the first `ftg-payload-visual` reader did. Proof used: field 5 decodes to the four map corners; district rings become simple polygons; a scale-bar anchor distance matches the screenshot. Re-derivation scripts live in `research/ftg-capture/critic2/`. Still open: persisted road segments are exactly half the configured `roadLength`.

## Added 2026-09-26 (lane confidence/dwellings-rule, Fable judge)

- **Analyzer call trees are time-sorted, not execution-ordered.** `profiler/analyze.mjs` l.130 sorts siblings by inclusive time (`.sort((a, b) => b.total - a.total)`). Nesting is valid evidence of structure; sibling order is NOT an execution order. `profile-dwellings.md` §3.1 and `_critic-dwellings` R14 printed `Namer.get`/`updateURL` in opposite orders for this reason; any "X runs last, so …" argument read from a tree is unsupported. Use re-entry probes (Shift+Enter / Ctrl+Enter), identical candidate streams or nesting instead. CONFIRMED on disk.
- **Dwellings (build 17195045) PRNG = Lehmer 48271 mod 2^31−1, same as MFCG/NG; the next Enter seed is the raw state after k draws** (k = 80–5 216 per generation; a direct load vs reaching the house by Enter differ by exactly one draw; view keys advance the stream 1 987 draws with 0 recorded `Random.float` calls — draw sites are inlined). **Hazard:** ≈ 1 generation in 5 reseeds its successor from the clock (`HouseType.assignSet → Random.reset → new Date()`; off-orbit 4/4 when the stack is recorded, on 18/18 when not), so "the Enter chain is deterministic given the loaded state and key history" holds only for clock-free histories; a settlement generator must store the full parameter set, never the chain. Ruled: A4 stream-only S 0.70 (docs/CONFIDENCE.md §9, docs/confidence/dwellings-ruling.md).
- **Stale receipt:** `captures/dwellings/_critic/permalink-decode.out.txt` holds the decoder's first-run entrance verdicts (4 of 8 wrong by an off-by-one); the corrected run is `permalink-decode.entrances.txt`. Cite the latter.

## Added 2026-09-27 (lane code/manor)

- **Fantasy Manor (itch 2851818, build 890, v1.0.0) is non-minified Haxe 4.0.3 and seed-replayable.** Its PRNG (Lehmer 48271 mod 2^31−1, inlined) is seeded ONCE in `Main` from the load millisecond via the `Date` constructor (a `Date.now` probe cannot see it); a 64×64 grain tile eats 16 384 draws before building 1; every recolour or toggle shifts all later buildings. Seed = the pass's first `console.jsonl` `t` + 0–43 ms: all five coverage/draw passes replayed exactly (39 counters × 46 generations; exact facet and stone RGB). Technique for any clock-seeded generator: bracket by the console timestamp, screen candidates on cheap model counts, confirm on every counter. Details: research/findings/code-manor.md §4 (check scripts live in the session scratchpad only).
- **Convert decimal colour constants with a tool, never by eye:** 13551030 = 0xCEC5B6 (not 0xCEC6B6); the by-eye slip broke the stone-colour replay once.
- **Profiled cold samples are not steady-state costs:** FM's `Manor.new` 0.6–1.7 ms (captures/manor/README.md) are the first three builds under the CPU profiler; the restated model runs ≈ 0.08 ms/building warm.

## Added 2026-09-27 (lane code/ftg-client, checkpointed)

- **FTG client chunk `ThreeJsPages-*.js` keeps its identifiers** (entry `index-*.js` is minified; its helpers are readable through ThreeJsPages' import aliases). It carries protobuf.js generated code for `com.fantasytowngenerator.api.protobuf` → the whole layout schema by name (research/findings/code-ftg-client.md §2.1). Edge types: 0 ROAD, 1 MAIN_ROAD, 2 DIRT_ROAD, 3 BORDER, 4 INVISIBLE, 5 WALL, 6 STONE_FENCE (not "rural lanes"), 7 STONE_WALL (the wall is in the graph), 8 SANDSTONE_WALL, 9 WOOD_WALL, 10 SMALL_ROAD, 11 WOOD_PIER, 12 STONE_PIER, 13 TRAIL, 14 WATERFRONT. Payload field 9 = ground-cover texture polygons (lawn/paving/sand/fields), NOT lots; 8.6 = lightPosition, not an entrance; 8.8 = roof shape; 8.9 = height.
- **The layout is decoded by generated JS in the main thread** (not a WASM decoder); the two WASM modules are CGAL straight skeleton (roofs) and Clipper. Server-side: generation, simulation (lit buildings, field 26). Client PRNG sfc32 + cyrb128; forests filled at render by a jittered grid seeded by settlement id + kind.

## Added 2026-09-27 (lane code/dwellings)

- **Dwellings' "1 in 5" clock reseed has an exact cause:** `HouseType.assignSet` rewinds the stream to its best trial's start; when list 2 meets zero rooms (every room of a ≤ 4-room house took a list-1 role) there is no trial and the rewind goes to the clock — furniture, lights, windows, chimneys, the name and the next seed then vary per load (read; the two-load check is still unexecuted). The facade style is drawn BEFORE the per-house reset, so it always depends on prior state. Details: research/findings/code-dwellings.md §4.2, C21–C23.
- **Draft sections from an earlier seat must be re-verified against the bundle before splicing:** the lane's own first draft said the name ignores the tags; the grammar asset's house nouns are in fact guarded by derived small/large/low/tall flags (structure checked by a words-masked script).
- **Hand-off hazard:** Dwellings drops any URL plan wider or taller than 11 cells and draws a random house instead; NG sends widths up to 16 (code-neighbourhood §2.12).
