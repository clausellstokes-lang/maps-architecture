## 1. Summary

**The simulator's physics is designed in weeks and integer cost units over a frozen digest, and the design has already decided that the digest's geometry comes from "the map" without ever saying which map.** Every FP volume that moves something — trade (TR), populations (POP), war circulation (WC), wayfare (WY), espionage (ES), route lifecycle (J), pestilence, rumours — reads one distance law, `hopWeeks`/`calibration` over the frozen `spatialDigest`, and declares in its own hazard section that authoring an absolute week literal is a trap because the realm's span is 2..8 march-weeks under per-digest normalisation [STATED DESIGN_FP_ARCH_WC.md:4992-5002; DESIGN_FP_ARCH_WY.md:285-299]. The owner's 2026-08-01/05 directives then made distance ABSOLUTE ("tens of miles and thousands of miles are different worlds"; "scales with the map's real miles/km. One calibration, all movers") [STATED DESIGN_REALM_DIRECTIVES.md:1578-1585; DESIGN_FP_ARCH_WY.md:214-217], which the code answered with a per-world datum, `spatialDigest.kmScale` (km per map-coordinate unit), a five-mode speed table (foot 150, cart 110, river 280, coastal 450, sea 900 km/week), and an "absolute arm" of the calibration — all landed DARK before `00b648c9` and still written by nobody: the creation flow that should supply the scale has zero callers, so every world, new or old, runs the legacy normalised read [OBSERVED src/domain/spatial/modeSpeeds.js:47-78; distanceRead.js:597-627; grep: `creationKmScale` has no src caller; STATED DESIGN_FP_ARCH_WY.md:256 bracket, FPQ-37]. The one ruling that names where the datum should come from says: the map's EXPORTED `distanceScale` + `distanceUnit` converted to km at canonisation, with `DEFAULT_KM_SCALE 3` demoted to a fallback whose unit the chair found wrong (FMG's default unit is miles, so "3" is 3 mi ≈ 4.83 km) [STATED DESIGN_FP_COHERENCE_FOLD.md:515, OD-FC-22, chair by delegation 2026-10-16].

**Terrain, elevation, water, climate and routes all enter through one door — the one-shot capture of seven pack arrays at canonize — and the design's own hazard notes list what that door cannot carry.** Elevation is a 0..100 height with two thresholds (land 20, mountain 60) and no gradient term, so relief between the two thresholds "is invisible to it" — hills unknowable, in this note's gloss [OBSERVED src/domain/spatial/spatialCost.js:52,68,289-292,385]; ocean-vs-lake is guessed from a bounding box because the feature array never crosses the bridge [OBSERVED waterBodies.js:1-60; audit §4.2]; river navigability is a flux band under FMG's cut [OBSERVED seaLanes.js:76-84]; the wind the fabric volume needs for "downwind, downstream" siting exists nowhere in the host; line of sight exists nowhere in any volume (zero hits in docs for intervisibility/line-of-sight/viewshed; in src only the interior VTT export's wall-derived `line_of_sight`, interiorExport.js:8-10, which is not a terrain viewshed) [OBSERVED grep]. The airship "parallel aerial cost field" of Phase 5.5 §4e is not built as a field at all: an airship is an institution-name regex that adds a modality weight (1.5) and a food-import coverage rate (0.3; 0.15 when the dock is besieged) [OBSERVED src/domain/spatial/tradeFlow.js:60,102,138; src/data/foodImportRates.js:18-19].

**The settlement-map fabric volume (DESIGN_FP_ARCH_MF.md) is the only host document that designs terrain as a generator input rather than a cost — and the fold has ruled it out of FP and into "the map program's own family".** Its three laws — terrain-first ("terrain and height first… everything else still a roll but BOUNDED to what makes the most sense based on the terrain"), forced-fact reconciliation ("account for if the user forces things that usually are incoherent with each other"), and morphology ("calibrate based on reality") — describe exactly a settlement-scale terrain solver that reads the whole dossier, finds sites instead of placing them, grows polycentric forms along connecting roads, solves mountain+ocean+port as a fjord, and renders strain as visible work [STATED DESIGN_FP_ARCH_MF.md:220-253]. The volume's realm coupling is thin and explicit: true exit-road bearings from the frozen digest's territory adjacency (MF-3), neighbour-edge annotations only when a campaign link exists and "on the TRUE BEARING of that neighbor in the realm's spatial layout" (§164a), a TRUE scale bar whose derivation home is still owed (MF-5), and a regional route skeleton "before nuclei" sourced from the route-network ledger's arterial seeds (§15.2) [STATED MF.md:193,196,214,443,479]. It persists nothing and says so; it is a projection, and the ruling that moved it (OD-FC-38) is the clearest statement in the corpus that a map program distinct from FP exists [STATED MF.md:12; DESIGN_FP_COHERENCE_FOLD.md:281,531].

**The port rule is the one piece of Phase 5.5 water design that is built and lit, and it is the model for every other derived fact.** PORT = GEOGRAPHY ∧ INSTITUTIONS, both derived at digest build, re-derived on founding events through a receipted re-canonize; geography is necessary, institutions sufficient; the sea/river edge set is a sibling slot beside the land field, materialised only when ≥2 eligible ports exist; water is an order of magnitude cheaper (SEA_COST_PER_DIST 12 against land's ~90..1,560 per cell-step) and high-capacity (10 against land's implicit 1, recorded and unenforced); storm season prices winter crossings ×2.5 and never severs [STATED PHASE55:715-758; OBSERVED seaLanes.js:14-30,76-121; navalLayer.js:270-285]. The ports-totality invariant (every port with a navigable counterpart carries a water edge) is route-lifecycle Law 6 and realm directive 11(c) [STATED DESIGN_ROUTE_LIFECYCLE.md:44-45; DESIGN_REALM_DIRECTIVES.md:1585-1588].

## 3. The three fabric laws (DESIGN_FP_ARCH_MF.md §5.-1, §5.-1c, §5.0), in full, and how they bind a settlement map generator

Provenance of the text: the volume's body is the chair's map-fabric charter of 2026-08-16 "VERBATIM… the charter's own bytes, unchanged"; the owner's quotations are embedded in the section titles and bodies; lane UF-1 added only the header, the ODQ citation map (§0.A) and the inventory (§0.B) [STATED MF.md:20-26,145-148]. The volume was LANDED on the ledger at `1d77ceb67` (2026-08-16), never on master, and reached master only inside the 2026-10-16 fold commit, where the chair ruled it OUT of FP — "a presentation program ('Zero simulation-engine changes; zero persisted-state changes', §0) that belongs to the map program's own family" (OD-FC-38) [STATED MF.md:10-12; FOLD:281,531]. Its decision rule, which "governs every decision in this family" (owner order §161j): reconcile HISTORICAL EVIDENCE with THE ABSOLUTE BEST POSSIBLE PRODUCT, regardless of risk — "History is the oracle… implementation risk is never a veto — a harder-but-truer mechanism beats an easier approximation everywhere the two diverge", with determinism, THE PROMISE and the §8 coherence laws "not risks to accept but the ground everything stands on" [STATED MF.md:156-158].

### 3.1 THE TERRAIN-FIRST LAW (§5.-1; owner order 2026-08-16: "terrain and height first… everything else still a roll but BOUNDED to what makes the most sense based on the terrain")

In my words. The generator's layer zero is the land. Before a nucleus, a road, a ward or a parcel exists, it derives a seeded LOCAL TERRAIN SUBSTRATE — a small heightfield with derived wetness and flow — that must be consistent with the settlement's canonical facts and deterministic from the settlement seed. The substrate "READS THE WHOLE DOSSIER" (owner emphasis, §161a): terrain type sets the landform family; water features set the water-relationship mode (§5.0b); the LOCAL RESOURCES chosen at generation shape the ground that must carry them ("ore implies workable slopes and spoil ground, fisheries imply the shore and shoal, timber implies the standing forest, quarry implies exposed stone"); trade-route access decides how many roads deserve to exist and how good their grades are; the neighbour link sets the bearing the main road actually leaves by. The land must be "the land its OWN economy could have grown from". The substrate persists nothing; it is the bounding surface every later roll samples against [STATED MF.md:220-222].

Its clauses:
1. Water obeys height — the river follows the valley the heightfield gives it, marsh collects where flow stalls, the coast takes the low edge; the §5.0b mode constrains the substrate ("a BANKSIDE town gets a bank worth sitting on") [MF.md:224].
2. Sites are FOUND, not placed — a suitability field (flat enough, dry enough, defensible, near water/road potential) is rolled over the substrate and the nucleus is the best site, or the nuclei the best several [MF.md:225].
3. THE POLYCENTRIC SUBSEED LAW ("the owner's example, adopted verbatim as mechanism") — when two viable sites are not adjacent (the defensible rise and the river landing; the ford and the crossroads), a road connects them FIRST and becomes a growth subseed; ribbon development accretes along it; "One-site towns cluster; two-site towns stretch; this is where real towns get their shapes" [MF.md:226].
4. Everything downstream is a BOUNDED roll — accretion lobes refuse steep or wet cells; streets prefer contours and gentle grades; the wall follows defensible lines; fields take the flats, terraces the slopes, pasture the rough; the noxious quarter goes "downwind AND downstream of the substrate's actual flow". "Randomness proposes; terrain disposes" [MF.md:227].
5. The order of generation, whole: terrain substrate → water → suitability → CONSTITUTION (the district-instance list from the membership roll, before any geometry) → nucleus/nuclei → connecting roads (the subseeds) → morphology governs the order character of growth within the terrain bound → organism anchoring and accretion → wards → streets/parcels → member seating → walls → states/history → paint [MF.md:228]. §15.2 later inserts a stage between terrain and nuclei: a REGIONAL ROUTE SKELETON (pre-settlement trade corridors, crossings, coastal paths; the route-network ledger's arterial seeds where a campaign exists) — "The crossroads exists before the crossroads town" [MF.md:479].
6b. THE TERRAFORMING LAW (owner §161b): higher tiers push back on the land to a bounded, appropriate extent, after growth establishes need — a levelled and revetted market terrace, drained marsh with its ditch grid, a cut mill race or canal, a causeway, terraced slopes, a dug moat, a quarry scar; bounds none below town, modest at town, substantial at city, "monumental-but-bounded at metropolis (a harbor mole, a diverted channel)"; THE VISIBLE-WORK RULE — "every terraform leaves its workings legible in ink… the land must LOOK worked, not conveniently reshaped; an edit with no visible work is a substrate cheat and reds the consistency pin"; terraforming interleaves growth at fixed finite points, "never iterate-to-convergence" [MF.md:229].
6. The substrate is fabric-layer machinery (cosmetic-deterministic, no persisted state); its consistency with canonical terrain facts is a pinned test: "a mountain-valley settlement whose substrate rolls flat plains is a RED" [MF.md:231].

### 3.2 THE FORCED-FACT RECONCILIATION LAW (§5.-1c; owner order 2026-08-16, §176: "account for if the user forces things that usually are incoherent with each other")

In my words. User-forced facts are TRUTH under the precedence law (§8.1) — "never errors, never silently dropped" — and the substrate's job is "to SOLVE for the land that makes ALL of them believable at once" [MF.md:235].
1. THE SOLVER, NOT A LOOKUP — for a forced combination (mountainside + ocean + port; desert + great river; marsh + stone city) the substrate runs as a constraint solver over landform families, "searching for the form under which every forced fact is most plausible — and Earth has already solved almost everything": mountain-meets-sea-with-port is the FJORD/CLIFF-HARBOR family (the town terraced up the slope, the port in the deep cove below); desert + river the flood-plain ribbon; marsh + city the piled-and-drained island town. "History is the solution catalog; the seeded roll picks among the reconciling forms, never among the contradicting ones" [MF.md:237].
2. STRAIN RENDERS AS WORK — switchback roads and cliff stairs, terraces with retaining walls, a breakwater, stilts, a rock-cut ramp; "A strained combination doesn't look wrong; it looks HARD-WON"; the terraform budgets flex for forced strain with the flex recorded [MF.md:238].
3. PRECEDENCE UNDER FORCE — user-truth > state > tier > terrain-plausibility > jitter; the consistency pin's assertion changes from "the land is what the economy implies" to "the land is the BEST reconciliation of everything forced, and every forced fact is honored on the map". "No forced fact may be omitted, misplaced into nonsense (the port on the peak), or quietly substituted" [MF.md:239].
4. THE HONEST RESIDUE — a true physical contradiction still renders every forced fact at its most defensible placement, the derivation records the strain, and the dossier's own coherence machinery carries the judgment; "the MAP never editorializes beyond its calm ink, and never breaks" [MF.md:240].
5. Deterministic: same forced config, same reconciliation, forever; the §109 acceptance set gains the owner's mountain–ocean–port exemplar [MF.md:241].

### 3.3 THE MORPHOLOGY LAW (§5.0; owner calibration order 2026-08-16: "calibrate based on reality")

In my words. "Pure geometry is reserved for the most orderly; the DEFAULT is historical organic accretion." Plan morphology derives from the settlement's ORDER character on a scale, never from aesthetic preference [MF.md:245]:
1. ORGANIC ACCRETION (the default — most of history): irregular street webs grown along the road fork, the river crossing, the terrain; path-dependent, asymmetric, wards of unequal size, walls that bend around what was already there — "Leonardo's own Imola is a decayed Roman grid gone organic; most real medieval towns never had a plan" [MF.md:247].
2. PARTIALLY REGULARIZED (middle order): an organic base with inserted regularity where authority acted — a straightened market street, a quarter rebuilt on a small grid after a fire (event-log-derived), a geometric citadel imposed on organic fabric [MF.md:248].
3. PLANNED GEOMETRY (the most orderly ONLY): concentric rings or full grids only when the canonical facts support a planning authority — strong centralized governance, a planned/military founding in the origin record, high civic order; "A theocratic planned city may be radial; a garrison foundation may be gridded; nothing else is" [MF.md:249].
The selector is a derivation over governance/power-structure fields + founding record + order state, with a §42/§43 tuning home at compile; acceptance requires both ends of the scale in the exemplar set "and the organic end must dominate the corpus in the same proportion it dominated history". INPUT GAP (MF-P1): no typed founding record exists (`settlementReason` is prose), so the PLANNED band is unreachable from canonical data — "Either the compile mints a typed founding field… or planned geometry is an AUTHORED OVERRIDE, never a derivation. A prose regex may not stand in for the missing field" [MF.md:251-253].

### 3.4 How the three laws bind a settlement map generator

## 4. The port rule and the water design of Phase 5.5 §4j, in full

§4j is "Water — sea lanes, rivers, and the PORT rule (owner, round 20; settles the keystone reservation)"; the thesis line: "Water becomes the HIGHWAY it historically was — but access is EARNED, not free" [STATED PHASE55:715-716].

### 4.1 The port rule as designed (owner)

PORT ELIGIBILITY = GEOGRAPHY ∧ INSTITUTIONS, both required, both derived [PHASE55:718-728]:
- PROXIMITY: the settlement must be in close proximity to navigable water — "coastal cell / river course / lake shore, read from the canon map — FMG already carries coastlines + rivers; the threshold is a digest-time derivation".
- CAPABILITY: the settlement must HAVE a water-access institution, mapped from the existing institution catalog at build time (dock, harbor, shipwright, fishery, ferry, port authority — "the build enumerates the actual catalog; no new authored flag").
- GEOGRAPHY IS NECESSARY, INSTITUTIONS ARE SUFFICIENT: "a landlocked settlement can NEVER buy its way onto the water; a coastal settlement WITHOUT a dock is a beach, not a port — and can BECOME a port by FOUNDING one" (the W-C3 founding lane "gains its most consequential candidate"). "Ports are therefore fully DERIVED and can EMERGE mid-campaign."

### 4.2 The sea/river edge set (the keystone reservation, settled)

Water lanes are a SEPARATE edge set in the frozen digest — "the PART VI air/teleport pattern — optional sibling edge sets beside the land cost field" — materialised only when ≥2 eligible ports exist. Sea lanes connect eligible sea-ports; river lanes connect river-ports ALONG the river course. "Port = the settlement's WATER GATE (the §2 gate concept, maritime)" [PHASE55:730-734].

### 4.3 Economics

"Water is cheap and big": the historical order-of-magnitude advantage — LOW cost, HIGH capacity vs land. Consequences: PORT CITIES as a distinct destiny beside the entrepôt ("a port-entrepôt is the richest thing on the map"); the ISOLATION INVERSION fixed — "an island with a harbor is a HUB, not a hermit (round-7 isolation now reads 'no viable LAND route AND no port')"; import-dependent coastal towns lean on the sea lane their granary math assumes [PHASE55:736-740].

### 4.4 Everything composes

- SIEGE: a port city's interdiction requires land AND SEA control; NAVAL BLOCKADE = holding the water gate; a blockade-runner is the maritime smuggler.
- PIRACY = maritime banditry: the §6 danger term on sea lanes; the smuggle network's sea arm moves contraband between ports that ban it.
- SEASONS: STORM SEASON — winter closes/prices-up the cheap sea route exactly when the granary math bites.
- INFORMATION: ship crews are a FAST, LONG-RANGE rumour carrier between ports ("two ports gossip across a sea the land takes a season to walk around"); port cities become information brokers between coastlines.
- MIGRATION: refugees take ship where ports exist, with passage costs that make it selective — "the desperate walk, the funded sail" [PHASE55:742-754].

V1 SCOPE (architect): edges + port-gates + blockade/piracy as danger terms + the carrier variant; NO fleet combat in v1 ("navies are a future wave if ever"). Determinism/dormancy: eligibility derived at digest time from canon map + institution roster; re-derived on founding events; "no ports ⇒ no edge set ⇒ prior bytes" [PHASE55:755-758].

### 8.1 What the counts say

[INFERRED] Everything the host wants at the SETTLEMENT (the charter, T7/T8, W1–W3, W8–W9, S3, S7, D14–D15, R8–R9) is supplied in richer form than the host's design asked for — a river crossing with discharge, width, depth and stage where the host asked "is there a river"; a wind where the host had none; a lake with an outlet where the host guesses from a bounding box. Everything the host wants at the REALM GRAPH is the thinner side: the port returns routes, costs, territory and positions, but not the digest's derived products the simulation actually reads every tick — the all-pairs integer matrix (D1), gates (A2 — answered since by the canon's crossings, J-RR.3; see the bracket above) and tiers (D10), per-segment terrain receipts (T2), candidate route sets (R7), route capacities (C2) and the `hidden` rung (M4). Two readings are possible and the host's own law picks one: proposal §6.1 says the host should receive "territory, gates, distances, routed polylines" through the port, which would extend `SettlementMapRecord`/`routes(world)` with a distance matrix and gate list in the host's cost law (the host already hands the law in through `costLaw`); or the host keeps building its digest from what the port returns, in which case it needs the territory raster and each route's cell sequence, which the port withholds by design ("the host reads derived facts; it never reads arenas", V13 §3.11.6). Either way the three version axes (geometry, cost law, overlay) must ride the port's format version, as proposal §6.1 already says.
