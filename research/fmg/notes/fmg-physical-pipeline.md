## 1. Summary

**Takeaway.** FMG builds a world as one strictly sequential list of ~40 steps over two shared globals: `grid` (a jittered-square-lattice Voronoi mesh, all per-cell typed arrays) and `pack` (a second Voronoi mesh built from a subset of grid points plus coastal midpoints, where everything downstream is indexed). Elevation is a `Uint8` 0–100 "height" with land at ≥20; climate (temperature, precipitation) lives on the grid, hydrology (rivers, lakes, flux) on the pack. Rivers are cell-centre polylines produced by a steepest-descent, single-flow-direction accumulation over an iteratively depression-filled copy of the heights; lakes are any non-border water body plus "deep depression" cells converted to water, with level = lowest shore − 0.1 and an evaporation-vs-inflow test deciding whether they have an outlet. Biomes are a 5×26 temperature/moisture lookup with four overrides. The whole thing is planar (equirectangular lat/lon box over a pixel rectangle), unit-light (pixels × a user "distance scale"), and deterministic from the seed only together with the full option set and the code version; the PRNG is re-seeded at several stage boundaries, so some stages are individually reproducible.

**Key-question answers in one line each** (details and citations in §3):

- Stage order: `grid → heightmap → markupGrid → depressionLakes → nearSeaLakes → mapSize → temperatures → precipitation → clearPack → clearGraphOverride → regraph → markupPack → defaultRuler → rivers → biomes → featureGroups → ice → …(human layers)…` [OBSERVED src/generators/generation-pipeline.ts:8-49]. Relief icons and ocean rings and coastline displacement are *not* pipeline steps; they are produced lazily at draw time from pipeline data [OBSERVED src/renderers/draw-relief-icons.ts:13; src/generators/ocean-generator.ts:399; src/generators/coastline-generator.ts:532].
- Elevation: `Uint8` 0–100; `SEA_LEVEL = 20`; land ⇔ h ≥ 20 [OBSERVED src/utils/heightUtils.ts:2-10]. Display metres = (h − 18)^exponent (exponent default 2), i.e. h=20 → 4 m, h=50 → 1024 m, h=100 → 6724 m; water depth = ((h−20)/h)×50 (negative), h=0 → −990 [OBSERVED src/utils/unitUtils.ts:59-72].
- Rivers: steepest-descent to the lowest neighbour (haven for coastal cells) over depression-filled heights; flux accumulates downstream in an integer `Uint16`; a cell becomes river when flux ≥ 30; confluence takeover by larger flux; lake outlets when lake inflow > evaporation; off-map exit marked with −1; width/discharge/length derived afterwards; rendered as a meandered polyline polygon through pack cell centres [OBSERVED src/generators/river-generator.ts:189-432, 507-595].
- Lakes: level = min shoreline height − 0.1 (fractional, on a Uint8 base) [OBSERVED src/generators/lakes.ts:12-16]; open/closed via an elevation-limit BFS and an evaporation (Penman-style) vs. shoreline-precipitation test [OBSERVED src/generators/lakes.ts:47-124]. **No groundwater or water-table concept exists** (no identifier or doc mentions one) [OBSERVED by grep over src and docs].
- Climate: temperature from row latitude (linear bands) minus 6.5 °C per km of display altitude; precipitation by marching "winds" along grid rows/columns dropping humidity with orographic terms; biomes from a temperature × moisture matrix [OBSERVED src/generators/temperature-generator.ts:119-168; src/generators/precipitation-generator.ts:204-305; src/generators/biomes-generator.ts:85-219].
- Resample/submap: generate a fresh grid for the target size with the *same seed*, copy h/temp/prec per new grid point from the nearest parent pack cell via the inverse projection, rerun grid markup/lakes/temperature/pack/markup/ice, then project every entity's coordinates and re-attach per-cell data from the nearest parent land cell; rivers are restored from the parent's meandered points, not regenerated [OBSERVED src/generators/resample.ts:447-499].
- Determinism: seed drives `Math.random` via Alea; it is re-seeded at grid, heightmap, markupGrid, precipitation, rivers, ice, feature naming; coastlines use a per-feature seed. Anything else that changes the option set, the graph size, the cell count, or the code (the authors explicitly keep legacy quirks "because fixing it changes every map") changes the map [OBSERVED see §3.0 and §4].
- Stated limitations: planar equirectangular model (globe view distorts near poles); rivers require every land cell to have a lower neighbour so depressions are filled or lake-ified; only mouth width is available; temperature is a world-wide annual mean; the data model is "poorly defined, inconsistent"; risk-mode edits always regenerate rivers/lakes/biomes [STATED, §4].

**Gaps.** No creator blog post was reachable (two web searches returned only mirrors and third-party notes); claims about "rivers may bend back" and "mountains" as creator statements could not be sourced and are recorded as gaps in §4. The `restoreRiskedData` path and the heightmap-editor brush internals were only skimmed. ## 3. Stage detail

### 3.0 Pre-pipeline: seed, options, sizing

- [OBSERVED] `generate(config)` calls `setSeed(precreatedSeed)`, then `Options.randomize()`, then `applyGraphSize()` (a DOM-sizing step), then `GenerationPipeline.run({graph})` (src/components/lifecycle.ts:52-65).
- [OBSERVED] Seed resolution: an explicit seed wins; otherwise on the first map a URL `?seed=` parameter (with a 13-char MFCG seed truncated by 4); otherwise a generated seed. `Math.random` is replaced by an Alea PRNG of that seed (src/components/seed.ts:8-21). Alea ^1.0.1, d3 ^7.9.0, delaunator ^5.0.1 (package.json:59-61).
- [OBSERVED] `Options.randomize` rolls (unless pinned): density step (default 4), template by weighted probability over the 14 templates, equator temperature gauss(25,7) clamped 20..35, north pole gauss(−25,7) in −40..10, south pole gauss(−15,7) in −40..10, precipitation gauss(100,40) in 5..500, distance scale gauss(3,1) in 1..5; and carries `resolveDepressionsSteps`, `lakeElevationLimit`, height exponent from stored requests (src/components/options-model.ts:221-311, 320-325).
- [OBSERVED] Defaults: graph 1280×800 px, 10 000 points; mapSize 100, latitude 50, longitude 50; temperature equator 27 / north −30 / south −15; precipitation 100; winds `[225,45,225,315,135,315]` (six 30° latitude tiers); distance unit km or mi, scale 3; height unit m or ft, exponent 2; `resolveDepressionsSteps` 250; `lakeElevationLimit` 20; editor `allowErosion` true (src/components/options-model.ts:59-105). Density step → cell count: 13 steps mapping 1 000 … 100 000 (src/data/graph-density.ts:3-26).
- [OBSERVED] If the tab reports no size, graph falls back to 1280×800 (src/components/options-model.ts:1-3) — so the *viewport* can change the extent and thus the map [INFERRED consequence].
- [STATED] "The execution order is the dependency graph"; there is deliberately no declared dependency list (docs/architecture/generation-pipeline.md:3-7, 48-50). Steps may be async; `heightmap` is the only async step (docs/architecture/generation-pipeline.md:33-35; src/generators/pipeline.ts:124-148).
- [OBSERVED] A test asserts that a new generation replaces the previous `pack` object with an empty one before regraph (src/generators/generation-pipeline.test.ts:31-56).

### 3.1 Grid: jittered square lattice + Delaunay/Voronoi

- [OBSERVED] Spacing = round2(sqrt(width·height / cellsDesired)); cellsX/cellsY = floor((size + 0.5·spacing − 1e−10)/spacing) (src/generators/grid-generator.ts:103-110). Points are laid row-major starting at (spacing/2, spacing/2), each jittered uniformly by ±0.9·(spacing/2) on both axes, rounded to 2 decimals and clamped to the extent (src/generators/grid-generator.ts:136-149). Hence the "generated number of cells is close but not equal" to the request [STATED grid-generator.ts:61; docs/architecture/data-model.md:22].
- [OBSERVED] Boundary pseudo-points ring the map at about one spacing outside the extent, every two spacings; they clip outer cells and get no cells of their own (src/generators/grid-generator.ts:112-133).
- [OBSERVED] Delaunator on points+boundary; the Voronoi class derives per real point: `cells.v` (vertex ids = triangle ids around it), `cells.c` (adjacent real cells), `cells.b` (1 if any neighbour was a boundary point); per triangle: `vertices.p` (circumcentre, kept as exact floats — a test explicitly guards against rounding because quantisation made cells "blocky" at high counts), `vertices.v` (3 adjacent triangles, −1 where none), `vertices.c` (3 cells) (src/generators/voronoi.ts:277-309, 401-433; src/generators/voronoi.test.ts:377-411).
- [OBSERVED] `Grid.findCell(x,y)` uses the *un-jittered* lattice index, so it is an approximate lookup (src/generators/grid-generator.ts:66-70). Heightmap tools use it to seed blobs [INFERRED: blob centres land in the lattice cell, not the true Voronoi cell].
- [OBSERVED] Grid typed arrays: `h` Uint8, `t` Int8, `f` Uint16, `temp` Int8, `prec` Uint8 (src/types/GridGraph.ts:6-12). Saves keep only points and boundary; cells/vertices are rebuilt on load (src/generators/grid-generator.ts:45-54; docs/architecture/data-model.md:16).

### 3.2 Heightmap: templates, blobs, lines, straits, masks, image

- [OBSERVED] `generate` re-seeds Alea with the map seed, then either runs a template or loads a precreated PNG; result replaces `grid.cells.h` (src/generators/heightmap-generator.ts:557-565).
- [OBSERVED] Template format: one step per line, `Tool a b c d`; tools are Hill, Pit, Range, Trough, Strait, Mask, Invert, Add, Multiply, Smooth (src/generators/heightmap-generator.ts:12, 508-549, 567-581). Numeric arguments may be ranges "a-b" resolved by `getNumberInRange` (fractional single values act as probabilities for the extra unit) (src/utils/probabilityUtils.ts:108-127); x/y placement ranges are percentages of width/height (src/generators/heightmap-generator.ts:67-76).
- [OBSERVED] Two cell-count-dependent exponents: a blob power (0.93 at 1k cells rising to ~0.997 at 100k; 0.98 default) and a line power (0.75 → 0.93; 0.81 default) (src/generators/heightmap-generator.ts:28-65). [INFERRED] these keep a feature's *pixel* footprint roughly constant as cell density changes, because decay is per neighbour ring.
- [OBSERVED] Hill: choose a start cell inside the x/y window (retry up to 50× while existing+new height would exceed 90), BFS outward where each ring's contribution = previous^blobPower × U(0.9,1.1), stopping below 1; added and clamped 0..100 (src/generators/heightmap-generator.ts:88-122). Pit: start must be land (h≥20, 50 retries); BFS subtracting a decaying amount with per-cell noise (124-159). Range: start in window, end random in the central region with Manhattan distance in [W/8, W/3]; ridge walked greedily toward the end with a 15 % chance per candidate of halving its distance score (adds wiggle); ridge and successive rings raised by h×U(0.85,1.15) with h ← h^linePower − 1 per ring until < 2; "prominences" every 6th ridge cell walk downhill and raise each visited cell to a 2:1 blend (161-270). Trough: mirror image with subtraction, end distance up to W/2, 20 % wiggle, start on land (272-384). Strait: width capped at cellsX/3, sub-1 widths are probabilities; a wiggly path across the map through the middle 40 % band, then rings where heights are raised to a power < 1 (flattening toward sea), with an overflow guard setting >100 to 5 (386-442). Add/Multiply: optional range `land` (≥20, land never pushed below 20, multiply relative to 20), `all`, or `a-b` (444-458). Smooth: blend each cell with the mean of itself+neighbours by fraction (460-470). Mask: radial-ish product mask (1−nx²)(1−ny²), negative power inverts, blended by |power| (472-485). Invert: with probability `count`, mirror across x, y or both by lattice index (487-506).
- [OBSERVED] Templates: 14 named templates, ids 0–13, each a script of 4–15 steps, with a probability weight used for random selection (weights: High Island 19, Archipelago 18, Continents 16, Low Island 9, Old World 8, Shattered 7, Mediterranean 5, Pangea 5, Volcano 3, Peninsula 3, Fractious 3, Isthmus 2, Atoll 1, Taklamakan 1) (src/data/heightmap-templates.ts:1-181). [STATED] a template is prescriptive but "there is always a significant level of randomness" (fmg-wiki/Heightmap-template-editor.md:197); heights 0 deep ocean … 100 max, 20 is land at sea level (fmg-wiki/Heightmap-template-editor.md:218).
- [OBSERVED] Precreated heightmaps: 23 real-world grayscale PNGs keyed by id (src/data/precreated-heightmaps.ts:8-32). Loading draws the image onto a canvas of exactly cellsX×cellsY pixels so 1 px = 1 grid cell, reads the red channel as lightness, applies a soft curve above 0.2 (l ↦ 0.2 + (l−0.2)^0.8), scales to 0..100 and floors (src/generators/heightmap-generator.ts:583-623). This is the only asynchronous step (Image onload) [OBSERVED]. Each precreated map carries a fixed world size/lat/lon position (src/generators/coordinates.ts:11-35).
- [OBSERVED] Editor image converter (not the pipeline): luminosity mapping puts L<13 to water scaled 0..20 and otherwise uses L directly as height; hue mapping separates water/land by hue (src/controllers/heightmap-editor.ts:2016-2031). [STATED] images are quantised to ≤100 colours and unassigned colours become ocean (fmg-wiki/Heightmap-customization.md:154-188). The "image overlay" wiki page is about a texture layer for tracing, not a generator input (fmg-wiki/Heightmap-image-overlay.md:331-369).
- [STATED] Editor exit requires at least 200 land cells (fmg-wiki/Heightmap-customization.md:103; src/controllers/heightmap-editor.ts:483).

### 3.3 Features on the grid (ocean / lake / island), distance field

- [OBSERVED] Flood fill from cell 0 (stack-based), grouping cells by land (h≥20) vs water; a water group touching any border cell is `ocean`, otherwise `lake`; land groups are `island`. During the fill, land cells adjacent to water get t=1 and the water cell t=−1. Then an outward march marks water cells −2, −3 … down to −10 (src/generators/features-generator.ts:77-159). `grid.features[0]` is a placeholder; ids start at 1 [OBSERVED 158; docs/architecture/data-model.md:60-64].

### 3.4 Deep-depression lakes

- [OBSERVED] For every non-border land cell that is a local minimum (height ≤ all neighbours), BFS through neighbours lower than h+`lakeElevationLimit`; if the search touches any water cell the depression is "not deep" and skipped; otherwise the cell and its equal-height neighbours become a lake (h=19, t=−1, new lake feature; surrounding land becomes coast t=1). Lakes are created sequentially so an earlier lake counts as reachable water for later checks. A limit of 80 disables the step (src/generators/grid-generator.ts:152-214). [STATED] "Creating lakes in deep depression areas" is a listed feature (fmg-wiki/Changelog.md:266); the editor's drainage overlay shows which depressions become lakes (fmg-wiki/Knowledge Base.md:73).

### 3.5 Open near-sea lakes

- [OBSERVED] For any lake cell, if a neighbouring coast cell (t=1) has h ≤ 22 and that cell has an ocean neighbour, the coast cell is drowned (h=19) and the whole lake is relabelled as that ocean. Skipped for the Atoll template (src/generators/grid-generator.ts:217-253). The comment cites Ancylus Lake as the motivation [STATED 216].

### 3.6 Map size and lat/lon box

- [OBSERVED] `partial` = some land feature touches the border. Precreated templates use a fixed [size %, lat shift %, lon shift %]. Random templates: with per-template probability (Pangea 1.0 … Low Island 0.1) and only if not partial, the map is the whole world [100,50,50]; else size ~ gauss from a per-template table (default expected 30, dev 20, min 15, max 100 or 80 if partial), latitude shift ~ gauss(40 or 60 with 50/50, 20) in 25..75, longitude 50 (src/generators/coordinates.ts:37-100).
- [OBSERVED] Box: latT = size%·180; latN = 90 − (180 − latT)·latShift; latS = latN − latT; lonT = min(aspect·latT, 360); lonE = 180 − (360 − lonT)·lonShift; lonW = lonE − lonT (src/generators/coordinates.ts:70-84). Pixel→lat/lon are linear (src/utils/commonUtils.ts:249-263), i.e. plate carrée [INFERRED]. [STATED] the globe view uses an equirectangular projection; 2:1 maps look best; distortion strongest near poles (fmg-wiki/Knowledge Base.md:809). The "world-from-pacific" entry carries a comment that its longitude "doesn't fit" [STATED src/generators/coordinates.ts:34].

### 3.7 Temperature

- [OBSERVED] Sea-level temperature by latitude: inside the tropics (16°N..20°S) T = Teq − |lat|·0.15; outside, linear from the tropic value to the respective pole value. Altitude drop for land only: round(((h−18)^exponent / 1000) · 6.5) °C, i.e. 6.5 °C per km of display altitude. Computed per *row* (latitude from the row's first point y) and stored as Int8 clamped to [−128,127] (src/generators/temperature-generator.ts:119-168). [STATED] temperature is an annual average and can only be set world-wide (fmg-wiki/Knowledge Base.md:481, 721). [STATED] the height exponent (1.5–2.2) "affects temperature and hence biomes" (fmg-wiki/Scale-and-distance.md:207).

### 3.8 Precipitation and winds

- [OBSERVED] `compute` re-seeds Alea with the map seed ("the same winds for the same map, whoever rolled before") (src/generators/precipitation-generator.ts:205). `modifier` = (cellsDesired/10000)^0.25 · precipitation%/100 (209-210).
- [OBSERVED] Winds: per grid row, latitude band (5°) → latitude modifier from an 18-entry table (x4 at 0–5°, x1 at 20–30°, x3 at 50–60°, x0.5 at 85–90°); tier = floor(|lat−89|/30) selects one of six wind angles; angle in (40,140) → row is a westerly source entering at its first cell, (220,320) → easterly entering at its last cell, (100,260) counts toward northerly, (>280 or <80) toward southerly (281-305). Free of randomness so the renderer reuses it [STATED 282-284].
- [OBSERVED] Passing a wind: initial humidity = maxPrec − h[first] (dry if ≤0). Per step: skip cells with temp < −5 ("no flux in permafrost"); over water, if the next cell is land add coastal precipitation humidity/rand(10,20) to it, else humidity += 5·modifier (capped) and the water cell gets +5·modifier ("need to correctly pour water through lakes"); over land, if the next cell is passable (h ≤ 85) precipitation = clamp(max(humidity/(10·modifier),1) + max(Δh,0)·(h_next/70)², 1, humidity), otherwise the whole humidity is dumped; 1 unit "evaporates" back if precipitation > 1.5; humidity decreases accordingly (212-254). Westerly/easterly max = 120·modifier·latMod per band; north/south max = 60·modifier·latMod·(share of rows), and for maps taller than 60° latitude the mean latMod is used (256-276). A band starting at cell 0 is skipped: "legacy quirk… fixing it changes every map" [STATED 225].
- [INFERRED] `prec` is a Uint8Array and additions are unchecked, so very wet cells (several winds + coastal bonus) can wrap modulo 256; nothing clamps the accumulation. Not confirmed by any test.
- [STATED] Precipitation 100 is "pretty wet"/Earth-like; 0 makes most of the map desert; default winds are already Earth-like (fmg-wiki/Knowledge Base.md:545-553). Display: prec × 100 mm (src/utils/unitUtils.ts:76-78).

### 3.9 Repack (regraph)

- [OBSERVED] Keep a grid point if it is land, or water with t ∈ {−1,−2}; among t=−2 points drop every fourth (index % 4 == 0) and drop all t=−2 points belonging to lakes (so lakes keep only their shore ring). For every coastal cell (t=±1) that is not on the border, add a midpoint to each same-t neighbour with a larger index whose squared distance ≥ spacing² (midpoint rounded to 1 dp, inherits the cell's height and grid parent). Rebuild Voronoi with the *grid's* boundary. `pack.cells.g` = parent grid id (Uint32); `pack.cells.h` = Uint8 copy; `pack.cells.area` = |polygon area| capped at 65535 (src/generators/pack-generator.ts:16-61). [STATED] purpose: denser exactly along coasts, deep ocean dropped (docs/architecture/generation-pipeline.md:265-266; docs/architecture/data-model.md:12).
- [INFERRED] Consequences: (a) deep-ocean geometry is gone from pack, so ocean rings are built from the grid; (b) a pack cell's climate is its parent grid cell's (`temp[g]`, `prec[g]`) — climate resolution is grid resolution; (c) coastal midpoint cells duplicate the parent's height, so coasts are flat shelves in pack heights.

### 3.10 Pack markup, havens, lake shorelines and levels

- [OBSERVED] Same flood fill as the grid but computing, for every coastal land cell, `haven` (nearest water neighbour by squared distance) and `harbor` (count of water neighbours); t=2 "landlocked" is marked for land adjacent to coast during the fill, then inland land is marked 3,4,… without limit (Int8 cap) and water −2…−10. Each feature gets a perimeter vertex chain (via `connectVertices` from a border cell), a clipped polygon area (oceans use summed cell areas because their ring is open at the border), `shoreline` (land cells touching the lake's vertices) and `height` (src/generators/features-generator.ts:164-330).
- [OBSERVED] Lake level: round2(min shoreline height − 0.1), default 20 if no shoreline (src/generators/lakes.ts:10-16). Levels are therefore fractional numbers on top of integer cell heights [INFERRED].

### 3.11 Default ruler

- [OBSERVED] Picks the largest land feature and spans a ruler between its leftmost and rightmost perimeter vertices inside a 100 px margin (src/generators/measurers-generator.ts:22-46). Cosmetic.

### 3.12 Rivers — full algorithm

Order inside `generate` [OBSERVED src/generators/river-generator.ts:414-431]: allocate `fl` Uint16, `r` Uint16, `conf` Uint8; `h = alterHeights()`; `Lakes.detectCloseLakes(h)`; `resolveDepressions(h)`; `drainWater()`; `defineRivers()`; `calculateConfluenceFlux()`; `Lakes.cleanupLakeData()`; if erosion allowed: `cells.h ← Uint8.from(h)` and `downcutRivers()`.

1. **Height tilt** [OBSERVED 434-444]: a float copy of pack heights where each land cell gains t/100 + mean(neighbour t)/10000 — the distance-from-coast field nudges interiors up so ties resolve toward the coast [INFERRED purpose].
2. **Closed-lake detection** [OBSERVED src/generators/lakes.ts:85-124]: per lake, BFS from the lowest shore cell through cells below lake.height + `lakeElevationLimit`; if it reaches an ocean cell, or a lake cell with a lower level, the lake is open; if lake.height+limit > 99 it is forced open. Writes `feature.closed`.
3. **Depression resolution** [OBSERVED 446-505]: up to `resolveDepressionsSteps` (default 250) iterations. Each iteration, for open lakes whose level ≤ min shore height, raise the level to min shore + 0.2 (only during the first 85 % of iterations; after 75 % of iterations such a lake is instead declared closed, its shore heights restored, and its level set to min shore − 1). Then for every non-border land cell in ascending height order, if its height ≤ the minimum of its neighbours' effective heights (a lake neighbour contributes the lake level), raise it to that minimum + 0.1. If five consecutive iterations show no net progress, abort and revert all heights to the tilted originals. Remaining depressions only produce a console warning ("Edit heightmap to fix") [STATED 504]. [INFERRED] this is an incremental (ε = 0.1) relaxation, not a priority-flood; it produces very flat filled floors (steps of 0.1 and 0.2) and can leave unresolved sinks; lake levels can rise above their shoreline during the process (restored afterwards for manual `add`, see 68-73).
4. **Drainage** [OBSERVED 201-290]: land cells sorted by tilted height descending. For each cell: `fl += prec[parent grid]/cellsNumberModifier` where cellsNumberModifier = (points/10000)^0.25. Lake climate data is computed first [OBSERVED src/generators/lakes.ts:47-82]: lake `flux` = sum of grid `prec` over shoreline cells; lake `temp` = mean shoreline temperature (first cell's if < 6 cells); `evaporation` = a Penman-style expression of temp and height-in-metres ((700·(T + 0.006·alt)/50 + 75)/(80 − T), "[1–11]") times the lake's cell count; `outCell` = lowest shore cell unless the lake is closed. When the current cell is a lake's out cell and the lake's flux exceeds its evaporation, the adjacent lake water cell receives `flux − evaporation`, is assigned an outlet river id (continuing the lake's main inlet river id if an adjacent cell already carries it, else a fresh id), and the water is passed on by `flowDown`; all inlet rivers get the outlet as parent. A border cell carrying a river appends −1 (off-map). Downhill target: for a lake out cell, the lowest neighbour not in the lake; for a coastal cell its `haven`; otherwise the lowest neighbour by tilted height. If the cell is not above its target it is skipped (unresolved depression). If flux < 30 (`MIN_FLUX_TO_FORM_RIVER`) the flux is just handed to the downhill *land* cell (lost at water); otherwise the cell is proclaimed a river (new id if none) and `flowDown` is called.
5. **flowDown** [OBSERVED 292-326]: if the target already has a river: if the incoming flux exceeds the target's own flux (fl − conf), the incoming river takes over the downstream cell (existing flux is recorded in `conf`, the old river becomes the tributary); else the incoming river becomes the tributary and its flux is recorded in `conf`. If the target is water: a lake records the largest-flux inlet as its `river`, sums `flux`, appends `inlets`; otherwise (ocean) nothing further. If land: fl[target] += incoming. The target cell is appended to the river's cell list.
6. **defineRivers** [OBSERVED 328-381]: rivers with fewer than 3 cells are discarded; `cells.r` set, `conf` flagged where two rivers share a cell; `source` = first cell, `mouth` = second-to-last cell (the last is the receiving water cell or −1); `parent` from the recorded tributary relation (0 = none); `widthFactor` = round2(1/(points/10000)^0.25), ×1.2 for main stems; `discharge` = fl[mouth] (comment "m3 in second"); `length` = polyline length of the meandered points in px; `sourceWidth` = min(fl[source]^0.9/500, 1); `width` (mouth, "km") = ((offset/1.5)^1.8) where offset = widthFactor·(lengthWidth + min(flux^0.7/500,1)) + sourceWidth and lengthWidth = n/200 + a Fibonacci progression /200 for the first 9 points (539-561, 629-633). A comment lists real mouth widths (Amazon 6000 m … Muchavets 40 m) as the calibration target [STATED 629-630].
7. **Confluence flux** [OBSERVED 399-412]: `conf` is recomputed as the sum of all inflows except the largest.
8. **Erosion** [OBSERVED 428-431, 383-397]: if allowed, pack heights are overwritten by the depression-filled floats truncated to Uint8 (so +0.1 fills vanish and only whole-unit raises persist [INFERRED]); then cells with h ≥ 35 and flux are lowered by floor(flux / mean flux of higher neighbours), at most 5 units. Without erosion (erase path with the box unchecked) heights are kept and, per docs, pack heights are snapped back to grid heights where the land/water side didn't flip [STATED docs/architecture/generation-pipeline.md:166-169].
9. **Geometry** [OBSERVED 507-537; src/utils/pathUtils.ts:425-487]: river points are pack cell centres (or user-edited anchors); a −1 cell is projected to the nearest map edge from the previous point. Between consecutive anchors, 0–2 perpendicular interpolation points are inserted with amplitude 0.5 + 1/step + max(0.5 − step/100, 0), where step starts at 10 for land sources and 1 for lake outlets; amplitude ×0.25 next to water cells; 2 points if step < 20 and the gap is > 8 px, 1 point if > 5 px; then an acute-angle relaxation pass. The rendered polygon offsets each point left/right by the width formula and joins with a Catmull-Rom curve (564-595; src/renderers/draw-rivers.ts:91-126). [STATED] meanders are computed at draw time and not persisted (docs/prd/meandering-river-routes.md:48-49).
10. **Representation** [OBSERVED]: rivers are an unordered array of objects with `cells` (pack cell ids, may repeat, −1 = off-map), optional `points`, parent/basin ids, discharge, length, width, sourceWidth, widthFactor (src/generators/river-generator.ts:13-30; docs/architecture/data-model.md:276-293). One river id per cell in `cells.r` (Uint16) — a confluence cell belongs to the winning river and is flagged in `conf` (docs/architecture/data-model.md:111-113). So rivers live on **cell centres as a separate polyline**, not on edges or vertices [OBSERVED].
11. **Deltas**: no delta/distributary mechanism exists; the only "branching" is the confluence takeover, and a river ends at the first water cell [OBSERVED absence; src/generators/river-generator.ts:308-323]. 
12. **Navigability** [OBSERVED 10-11, 774-777]: a cell is navigable if it has a river and flux ≥ 100; drain-feature resolution walks outlet chains through open lakes to the final ocean or closed lake (779-827; tests src/generators/river-generator.test.ts:42-161). [STATED] a river needs "every land cell to have a lower neighbour", hence depression filling or lakes (fmg-wiki/Knowledge Base.md:73).
13. **Manual add** [OBSERVED 60-187]: a river started at a point descends to the lowest neighbour, joining an existing river either as tributary (if shorter than the upstream part of the existing river) or by taking over its downstream cells; errors on depressed cells.

### 3.13 Units of hydrology

- [OBSERVED] flux is an integer accumulation of grid `prec` per cell scaled by cell count; labelled m³/s in the data model and UI but never converted (docs/architecture/data-model.md:289; src/generators/river-generator.ts:356). Length is px of the meandered path, converted for display by `length × distanceScale` in the user unit (src/utils/unitUtils.ts:183-187). Width is produced in "km" by an empirical power of the px offset — it is not derived from distanceScale [OBSERVED 631-633]. [STATED] only the mouth width is available (fmg-wiki/Knowledge Base.md:473).
- [OBSERVED] distance scale: default 3 units per px, randomised gauss(3,1) in [1,5]; UI range 0.01–20 (src/components/options-model.ts:74, 288-290; fmg-wiki/Scale-and-distance.md:195). Area = px² × scale² (src/utils/unitUtils.ts:228-232). The default 1280×800 px map at scale 3 is thus 3840×2400 km [INFERRED].

### 3.14 Lakes — classification and lifecycle

- [OBSERVED] Subtypes assigned in `featureGroups`: frozen if lake temp < −3; lava if level > 60, < 10 cells and firstCell % 10 == 0; with no inlets and no outlet: dry if evaporation > 4×flux, sinkhole if < 3 cells and firstCell % 10 == 0; salt if no outlet and evaporation > flux; else freshwater (src/generators/features-generator.ts:474-486). Dry, frozen and lava are non-navigable (64). Island subtypes by cell count relative to grid size (continent > N/10, island > N/1000, else isle; lake_island if the preceding cell's feature is a lake) (466-472); ocean subtypes ocean > N/25, sea > N/1000, gulf (503-508).
- [OBSERVED] `cleanupLakeData` drops transient `river/enteringFlux/outCell/closed`, rounds level to 3 dp and keeps only inlets/outlet that still exist (src/generators/lakes.ts:29-45).
- [OBSERVED] No groundwater, water table, infiltration or baseflow concept anywhere; precipitation enters flux directly (grep over src/generators and docs found no such identifier). Lakes in deep depressions are created by the heightmap stage, not by hydrology (§3.4).

### 3.15 Biomes

- [OBSERVED] 13 default biomes (0 Marine, 1 Hot desert, 2 Cold desert, 3 Savanna, 4 Grassland, 5 Tropical seasonal forest, 6 Temperate deciduous forest, 7 Tropical rainforest, 8 Temperate rainforest, 9 Taiga, 10 Tundra, 11 Glacier, 12 Wetland) each with habitability (0–100), relief icon density (0–250), a relief pool and a movement cost (src/generators/biomes-generator.ts:19-82). The lookup matrix is 5 moisture bands × 26 temperature bands of biome ids 1–10 (85-91). Up to 255 biomes; custom ones can be added for painting (151-168).
- [OBSERVED] Moisture per pack cell = round(4 + mean of (own `prec[g]` (+ max(flux/10, 2) if a river) and land neighbours' `prec[g]`)); temperature = `temp[g]` (116-131). Rules: water → 0; temp < −5 → glacier; temp ≥ 25 and no river and moisture < 8 → hot desert; wetland if temp > −2 and (moisture > 40 and h < 25, or moisture > 24 and 24 < h < 60); else matrix[min(moisture/5,4)][clamp(20 − temp, 0, 25)] (203-219). [STATED] matrix values are "generator configuration, not map state" (docs/architecture/data-model.md:501).

### 3.16 Relief icons (lazy)

- [OBSERVED] Generated when the relief layer is first drawn and `pack.relief` is empty, or on explicit regenerate (src/renderers/draw-relief-icons.ts:13; src/components/map-commands.ts:716). Cells are visited in shuffled order; water and river cells get none; a cell is claimed by the first matching rule (defaults: snowy mountains h 71–100 with temp ≤ −1, mountains h 71–100, hills h 50–70; rule icon size grows 0.8 per height unit above the rule's minimum, from 20.8 to 44 for mountains, 8–12 for hills) else by its biome pool; points are Poisson-disc samples inside the cell polygon at a spacing 2/(density/100)/styleDensity; output sorted by box bottom for z-order (src/generators/relief-generator.ts:64-106, 191-274; test src/generators/relief-generator.test.ts:49-65). [OBSERVED] no Alea re-seed in the module, so icon placement depends on PRNG state at draw time [INFERRED non-reproducible from seed alone]. [STATED] rules and pools semantics in docs/architecture/data-model.md:427-448 and docs/domain/glossary.md:331-335.

### 3.17 Ice

- [OBSERVED] Re-seeds Alea. Glaciers: polygons of grid land cells with temp ≤ −8 via an isoline tracer, clipped to the map. Icebergs: grid water cells not in lakes with temp ≤ 0, 20 % of eligible cells, size from normalised temperature (×0.8, /1.3 on the coast ring, ×U(0.8,1.2), clamped 0.1–1), polygon = cell polygon shrunk toward its centre (src/generators/ice-generator.ts:259-305). Stored as `pack.ice` with ids and optional offsets (docs/architecture/data-model.md:416-424).

### 3.18 Ocean layers (lazy)

- [OBSERVED] For each requested distance t (presets like −1,−3,−6 or −1…−9), trace closed rings around the grid cells with `t` equal to that value by walking vertices whose adjacent cells straddle t and t−1, keep every (1+2|t|)-th vertex except border ones, clip to the map; returned in preset order for stacking (src/generators/ocean-generator.ts:386-466; presets src/data/ocean-patterns.ts:1-9). Render-only, derived from `grid.cells.t`.

### 3.19 Coastline (lazy, render-time)

- [OBSERVED] The feature's vertex chain is simplified (tolerance 0.3) and clipped; each non-border edge is recursively midpoint-displaced up to `maxDepth` (default 4) with amplitude baseAmplitude·√len·roughness decaying by 0.9 per level; roughness is two-octave smoothstep value noise on a lattice of `roughnessScale` (60 px) keyed by position, contrast-powered, thresholded by `smoothThreshold` (0.25; ×2 for lakes); displacement noise is a murmur-style hash of the quantised (1/64 px) endpoints, so edits stay local; the seed is Alea(`<mapSeed>_c<featureId>_<variant>`) (src/generators/coastline-generator.ts:464-657; tests src/generators/coastline-generator.test.ts:391-451). [STATED] only the outline changes; cells, areas, ports stay (fmg-wiki/Coastline-Editor.md:117); settings live in `options.map.coastline` and per-feature overrides (docs/architecture/data-model.md:81).

### 3.20 Graph overrides (wrap tool)

- [OBSERVED] Moved pack vertices are stored as [original, edited] pairs; on rebuild an override is applied only if the rebuilt vertex still has the recorded original coordinates; cell and feature areas are refreshed (src/generators/graph-override.ts:544-620; tests src/generators/graph-override.test.ts:299-359). Cleared at each generation (src/generators/generation-pipeline.ts:18).

### 3.21 Resample / submap / transform

- [OBSERVED] `Resample.process`: deep-clones grid and pack; precomputes each parent river's meandered points; sets the point count from the density slider; generates a **new grid with the same map seed** at the (unchanged) extent; for each new grid point, inverse-projects into the parent, finds the nearest parent pack cell (quadtree) and copies `h`, `temp`, `prec` from its parent grid cell; if scale ≥ 2 smooths heights with neighbours while preserving the land/water side (water capped at 19, land floored at 20); reruns markupGrid, deep-depression lakes, near-sea lakes, `Coordinates.calculate`, `Temperature.generate` (so temp is recomputed, prec is copied), `Pack.generate`, `markupPack`, `Ice.generate`, default ruler; then restores per-cell data (biome, flux, suitability and population scaled by area ratio/scale, culture, state, burg, religion, province, good) from the nearest parent *land* pack cell; restores rivers by projecting meandered points, clipping to the map, mapping back to cells, scaling widthFactor by `scale`, and recomputing parent/basin/length; restores cultures/burgs/states/routes/religions/provinces/feature details (subtype, group, name, note, height from the parent feature at the projected first cell)/markers/zones/journeys/economy (src/generators/resample.ts:26-499). Test: a resample at density 2 yields ~2000 grid points (src/generators/resample.test.ts:456-479).
- [OBSERVED] Submap: region = current viewport widened to the canvas aspect; projection is an affine (x − x0)·scale; `mapSize`, latitude, longitude, distance scale and population scale are divided/recomputed by `scale` so the submap keeps its real-world size (src/controllers/submap-tool.ts:79-140). Transform: rotation/mirror/shift with scale 1 (src/controllers/transform-tool.ts:199-211).
- [STATED] "Resample … generates a fresh grid for the target size, resamples height/temp/prec from the parent by inverse projection, re-runs markupGrid → markupPack → ice → defaultRuler, then restores cells, entities and notes from the parent" (docs/architecture/generation-pipeline.md:199-202); "it's still a new map, so some data can be changed" (fmg-wiki/Knowledge Base.md:649).
- [INFERRED] Identity preservation is by *coordinates*, not by ids: features are re-identified by where their first cell lands in the parent; rivers keep their ids and geometry but their cells are re-found by nearest pack cell, so hydrology is not re-derived from the resampled heights (a submap's rivers can disagree with its re-filled heights).

### 3.22 Heightmap-editor paths (Keep / Risk / Erase)

- [STATED] Keep copies edited grid heights into pack via `cells.g` and cannot change the coastline; Risk re-runs markupGrid → (lakes if erosion) → temperature → precipitation → regraph → markupPack → GraphOverride.restore → rivers (if erosion) and re-attaches snapshotted per-cell data by grid index; Erase runs the ErasePipeline (docs/architecture/generation-pipeline.md:155-203). [OBSERVED] Risk forces any grid cell holding a burg to h ≥ 20 before re-markup (src/controllers/heightmap-editor.ts:623-627) and keeps river arrays only when erosion is off (598-620, 676-690). [STATED] rivers, lakes and biomes are always regenerated after a heightmap edit even in Risk mode (fmg-wiki/Knowledge Base.md:585, 341).
- [OBSERVED] The editor's "Show drainage" overlay computes a **priority-flood fill** (FlatQueue seeded from water and border cells, ε = 1e−4) then single-direction targets to the lowest *filled* neighbour, accumulates flux in one descending pass with the same per-cell precipitation scaling as the river generator, and flags rivers at flux ≥ 30 — i.e. the overlay already contains a priority-flood D8-style model that the generator itself does not use (src/renderers/overlays/drainage.ts:99-164). [STATED] the overlay hatches depressions that will be filled and, in blue, those deep enough to become lakes (fmg-wiki/Knowledge Base.md:73; fmg-wiki/Heightmap-customization.md:94-97).

### 3.23 What the seed and options control (consolidated)

- [OBSERVED] `Math.random` is globally replaced by Alea(seed) at: setSeed (src/components/seed.ts:20), Grid.generate (grid-generator.ts:20), HeightmapGenerator.generate (heightmap-generator.ts:558), Features.markupGrid (features-generator.ts:109), Precipitation.compute (precipitation-generator.ts:205), Rivers.generate (river-generator.ts:190), Ice.generate (ice-generator.ts:263), Features.defineNames (features-generator.ts:517). Coastlines use their own per-feature seed (coastline-generator.ts:507-509). `gauss` uses d3 randomNormal sourced from the current `Math.random` (src/utils/probabilityUtils.ts:49-52).
- [OBSERVED] Inputs that change the physical result besides the seed: extent width/height (spacing, boundary, lattice), cell count (spacing, blob/line powers, cellsNumberModifier in precipitation and flux, widthFactor), template id, precipitation %, three temperature anchors, six wind angles, height exponent (temperature → precipitation → biomes → lake evaporation), `lakeElevationLimit`, `resolveDepressionsSteps`, mapSize/latitude/longitude pins, erosion toggle (editor paths), and the Atoll special case. Distance scale and distance unit only affect display and routing distances [OBSERVED §3.13]. Relief icons additionally depend on style density and draw-time PRNG state (§3.16).
- [STATED] A seed "is not an identity: regenerating with the same seed makes a different Map" — in the glossary this refers to map *identity* (map id), not geometry (docs/domain/glossary.md:276-277). Code comments show the maintainers treat byte-for-byte reproduction across versions as a goal they sometimes sacrifice ("fixing it changes every map"; range randomness compared "to keep seeded generation identical to the legacy checks") (src/generators/precipitation-generator.ts:225; src/generators/heightmap-generator.ts:186).
- [INFERRED] Cross-engine determinism: everything is IEEE double arithmetic plus `Math.pow` with fractional exponents (blob/line powers, flux^0.7) and trig in meanders; JS engines may differ by an ULP on transcendental functions, which can flip a floor/round in rare cases. The PNG path depends on canvas image downscaling, which browsers implement differently. Neither is documented by FMG.

## 4. Known limitations and creator-stated caveats

Stated by creator/docs:
- [STATED] Planar model: the map is a lat/lon box with linear pixel↔degree mapping; the globe view is an equirectangular projection, "distortion is the strongest near the poles", 2:1 aspect best (fmg-wiki/Knowledge Base.md:809; src/utils/commonUtils.ts:249-263).
- [STATED] "Rivers need every land cell to have a lower neighbour to flow to, so on finalization the generator fills closed depressions or turns deep ones into lakes" (fmg-wiki/Knowledge Base.md:73). Unresolved depressions only warn: "Edit heightmap to fix" (src/generators/river-generator.ts:504).
- [STATED] Only the mouth width of a river is available (fmg-wiki/Knowledge Base.md:473); width/source width/width modifier are the editable knobs (fmg-wiki/River-Editor.md:93-96).
- [STATED] Temperature is an annual mean and can only be set world-wide; height exponent changes it (fmg-wiki/Knowledge Base.md:481, 721; fmg-wiki/Scale-and-distance.md:207).
- [STATED] Precipitation 100 ≈ "pretty wet" Earth-like; default winds "already similar to Earth" (fmg-wiki/Knowledge Base.md:545-553).
- [STATED] Lakes can only be created through the heightmap; any heightmap edit (even Risk mode with erosion off) regenerates rivers, lakes and biomes; Risk mode "can potentially cause some errors" (fmg-wiki/Knowledge Base.md:341, 425, 585; fmg-wiki/Heightmap-customization.md:57-59).
- [STATED] The data model "is poorly defined, inconsistent and not well-documented" (docs/architecture/data-model.md:1). `pack.cells.prec` is "in unspecified scale" (docs/architecture/data-model.md:93).
- [STATED] Non-pipeline rebuild paths (Keep/Risk/Resample) "can silently fall behind when a generation step is added" (docs/architecture/generation-pipeline.md:175-178).
- [STATED] Coastline displacement is cosmetic; cells, areas and ports are untouched (fmg-wiki/Coastline-Editor.md:117). Point count at Detail 5 "can reach hundreds of thousands" (fmg-wiki/Coastline-Editor.md:159).
- [STATED] The precipitation band quirk and the Uint16 area truncation are known and kept (src/generators/precipitation-generator.ts:225; src/generators/resample.ts:107-108).
- [STATED] Editor needs ≥ 200 land cells to finalise (fmg-wiki/Heightmap-customization.md:103).
- [STATED] "world-from-pacific" position "longitude doesn't fit" (src/generators/coordinates.ts:34).

Observed/inferred limitations (not stated by the creator):
- [INFERRED] Depression resolution is an ε-increment relaxation with an iteration cap and an abort heuristic, so flat floors and unresolved sinks are possible; the drainage overlay uses a real priority-flood but the generator does not (src/generators/river-generator.ts:446-505 vs src/renderers/overlays/drainage.ts:110-132).
- [INFERRED] Flow routing is single-direction steepest descent on Voronoi adjacency (≈ D-6/D-7 on an irregular mesh); "rivers may bend back" is plausible because meander offsets are perpendicular insertions between cell centres with step-dependent amplitude, and the takeover rule can re-route the downstream cells of an existing river. I found **no creator statement** using those words (gap).
- [INFERRED] Ocean heights are not simulated (deep ocean points are dropped at regraph; `t` is a hop count, not bathymetry); display depth is a formula of h.
- [OBSERVED] No deltas, no braiding, no groundwater, no sediment/erosion beyond a ≤5-unit downcut, no seasonal variation, no coriolis/sphericity in winds (winds are axis-aligned marches along grid rows/columns).
- [OBSERVED] Climate resolution equals grid resolution; pack midpoint cells inherit parent climate and heights.
- [OBSERVED] `Uint8` precipitation and `Uint16` flux can overflow silently (§3.8; src/generators/river-generator.ts:414).
- [OBSERVED] Height has no absolute datum: metres are derived by (h−18)^exponent, with exponent a *display/unit* option that nonetheless feeds temperature and lake evaporation (src/utils/unitUtils.ts:59-72; src/generators/temperature-generator.ts:137-152; src/generators/lakes.ts:60-64).

Gaps:
- Creator blog posts (azgaar.wordpress.com, cited in docs/architecture/data-model.md:12) were not reachable via two web searches (results were mirrors and third-party notes), so any blog-level statements of intent/limitations are unsourced here.
- I did not verify the exact behaviour of `Uint8Array.from` on fractional filled heights beyond the language semantics (ToUint8 truncates toward zero) [INFERRED].
- The wiki "Heightmap-image-overlay" page documents a texture-overlay workflow, not an input-image heightmap pipeline; the actual image→height pipeline lives in the editor converter and the precreated loader (§3.2).

## 5. Implications for a native SettlementForge world regime

Target: a raster-plus-graph world model in metres (exact integer-centimetre planar kernel downstream) with a D8 + priority-flood hydrology, handing boundary conditions to a settlement frame (PLAT).

| Stage | Verdict | Reasoning and mapping |
|---|---|---|
| Mesh (jittered lattice + Voronoi) | GENERALIZE | Keep the idea of one *coarse* regular lattice for climate and a *refined* graph near coasts, but on a raster: a coarse climate raster (FMG grid analogue) and a fine DEM raster (pack analogue) with the fine raster's resolution chosen by distance-to-coast/river rather than a Voronoi repack. FMG's `cells.g` parent-index pattern maps directly to a fine→coarse index map. Drop Voronoi for the world; keep a graph only as the river/lake/feature network. (src/generators/grid-generator.ts:103-149; src/generators/pack-generator.ts:16-61) |
| Heightmap templates (blob/line/strait/mask/invert/add/multiply/smooth) | KEEP (as a raster op set) | The ten template tools are resolution-independent when expressed as kernel operations: hills/pits = radial decay with per-ring noise, ranges/troughs = noisy polyline ridges with ring decay and "prominence" spurs, straits = power-law trench, mask = separable window, invert = mirror. Replace the cell-count-dependent blob/line powers by decay-per-metre so footprints are defined in metres, not rings (src/generators/heightmap-generator.ts:28-65). Keep the template DSL and the 14-template weighted catalogue as a seedable preset list (count/shape only; do not copy values). |
| Height representation (Uint8 0–100, sea=20, metres=(h−18)^e) | REPLACE | Store elevation in metres (integer cm fits the PLAT kernel) with an explicit datum: sea level = 0 m, bathymetry negative. FMG's land floor at h=20 → 4 m and the exponent-as-unit-option coupling into temperature/evaporation (src/utils/unitUtils.ts:59-72; temperature-generator.ts:149-152) are the main things to avoid. Keep the *decisions*: land ⇔ z ≥ datum; coast flag; a bounded max altitude (FMG's h=100 ≈ 6.7 km at e=2). |
| Precreated/PNG heightmaps | GENERALIZE | 1 px = 1 cell sampling with a soft tone curve is fine for a raster; store the image-to-metre curve explicitly (src/generators/heightmap-generator.ts:583-623). |
| Features & distance field (flood fill; ocean = touches border; lake = enclosed) | KEEP | Identical semantics on a raster with 4/8-connectivity; the land/water distance field (t) is cheap and FMG uses it for repack density, haven/harbor, tie-breaking and ocean rings (src/generators/features-generator.ts:108-159, 164-330). Compute it in metres (true distance transform) instead of hop counts. |
| Deep-depression lakes & near-sea breaching | REPLACE with priority-flood | FMG's two ad-hoc steps (local-minimum BFS with an elevation limit; breach coast cells ≤ 22) are what a priority-flood with a spill-height test gives for free: fill → if fill depth > lake threshold, water; if the spill saddle is within a breach tolerance of sea level, breach. Keep `lakeElevationLimit` as "max fill depth before a basin becomes a lake" in metres (src/generators/grid-generator.ts:152-253; the editor overlay already does exactly this: src/renderers/overlays/drainage.ts:110-132). |
| Map size / lat-lon box | KEEP (explicit) | Keep an equirectangular lat/lon box for climate only; the planar assumption is acceptable for a settlement-scale world as long as the extent is small in degrees. Record latN/latS per row for temperature (src/generators/coordinates.ts:70-84). |
| Temperature | KEEP | Latitude bands + 6.5 °C/km lapse on metres is standard; compute on the coarse climate raster, in integer tenths of °C rather than Int8 °C (src/generators/temperature-generator.ts:119-168). |
| Precipitation / winds | GENERALIZE | The row/column wind march with orographic drop (Δz·(z/zmax)², passable ≤ 85 % of max, dump at barriers), coastal bonus and evaporation from water is cheap and gives rain shadows; generalise to arbitrary wind direction on a raster (march along the wind vector with bilinear sampling) and to mm/yr units with clamping (no Uint8 wrap). Keep the latitude modifier table shape (18 five-degree bands). Make the coastal `rand(10,20)` noise explicit and seeded (src/generators/precipitation-generator.ts:212-279). |
| Repack | REJECT | Not needed with a raster; replace with a fine DEM raster plus coarse→fine index map. The one thing to preserve is *extra resolution along coasts and rivers* (achievable by a refined raster tier or by the settlement frame's own resampling). |
| Rivers: routing & accumulation | REPLACE with D8 + priority-flood | FMG is single-flow steepest descent on an irregular graph over ε-relaxed heights with a `MIN_FLUX` threshold and flux-based confluence takeover (src/generators/river-generator.ts:201-326). A D8 over a priority-flood-filled DEM (with ε gradient on flats) reproduces every needed outcome (unique outlet per cell, accumulation, confluences) deterministically and without unresolved sinks. KEEP: the river threshold concept (flux ≥ 30 FMG-units ≈ a drainage-area/discharge threshold in m³/s computed from rainfall × area); off-map exits as explicit boundary flux; lake inlets/outlets as graph edges. |
| Rivers: discharge, width, length | GENERALIZE | Replace FMG's unit-less flux and empirical width (px offset^1.8 "km") with discharge Q = Σ(P − E)·A in m³/s and a hydraulic-geometry width w = a·Q^b (FMG's calibration list of real mouth widths at river-generator.ts:629-630 is a useful sanity set). Length in metres along the centreline. |
| Rivers: meanders, geometry | GENERALIZE | FMG's draw-time perpendicular interpolation with step-dependent amplitude and the "startStep phase" trick is a rendering device, not hydrology (src/utils/pathUtils.ts:425-487; docs/prd/meandering-river-routes.md:48-59). For PLAT, produce a centreline polyline with width per vertex (and bank polygons) as *data*, so the settlement frame receives river entry/exit geometry it can snap to integer-cm. |
| Rivers: deltas | REPLACE | FMG has none. If deltas are wanted, derive them from low slope + high discharge at the coast as a separate stage. |
| Lakes: level, open/closed, evaporation | GENERALIZE | Keep: level = spill height (priority-flood gives it exactly, no −0.1 hack: src/generators/lakes.ts:12-16); open iff inflow > evaporation (lakes.ts:47-82, river-generator.ts:211-235); subtype rules (frozen by temp, salt/dry by evaporation ratio) (features-generator.ts:474-486). Replace the Penman-ish constant with an explicit evaporation rate in mm/yr × lake area. Groundwater: FMG has none; PLAT needs at least a water-table proxy — recommend "water table = max(lake/river stage nearby, DEM − depth-to-water from distance-to-stream)" as a new stage, since nothing in FMG supplies it. |
| Erosion / downcut | REJECT (or optional) | FMG's ≤5-unit downcut on cells ≥ 35 is cosmetic (river-generator.ts:383-397). With a real D8 model, use a stream-power incision pass only if visual valleys are needed. |
| Biomes | KEEP | A 5×26 (moisture × temperature) matrix with four overrides (water, permafrost, hot desert, wetland by moisture and altitude) is simple and reproducible; port it as a configurable table in mm/yr and °C (biomes-generator.ts:85-91, 203-219). Keep the "moisture = local rain + neighbour mean + river bonus" smoothing — it is a cheap stand-in for soil moisture. |
| Relief icons | REJECT (world) | Pure cartographic decoration; if desired, derive from slope/altitude bands at render time. Note FMG's draw-time unseeded placement (§3.16) as an anti-pattern. |
| Ice | KEEP (trivial) | Threshold on temperature over land/sea; seedable (ice-generator.ts:259-305). |
| Ocean rings | REJECT | Render-only. |
| Coastline fractalisation | GENERALIZE | Position-keyed deterministic noise with per-feature seeds (coastline-generator.ts:507-657) is a good pattern for sub-cell detail that must survive local edits; apply it to the world→frame handover (coast polyline refinement) rather than to the world DEM. |
| Resample / submap | GENERALIZE | The important design point: a submap re-samples *fields* (h/temp/prec) and re-derives *topology* (features, lakes, pack) but *copies* rivers and entities by projected coordinates (resample.ts:447-499). For SettlementForge, the world→frame handover should instead re-derive hydrology inside the frame from boundary conditions, so the frame's D8 agrees with its DEM. Keep the "preserve identity by projected position, drop what falls outside, scale per-area quantities by area ratio" rules. |
| Pipeline runner | KEEP | A declared ordered step list with per-step timing, a context flag for partial reruns (`erosion`), and explicit "which paths rebuild what" table (docs/architecture/generation-pipeline.md) is worth copying as process. |
| Determinism model | GENERALIZE | Re-seed per stage from (seed, stage name) rather than sharing one global stream, so a change in one stage's PRNG consumption does not shift later stages (FMG only partially does this: §3.23). Freeze option snapshots into the world record (FMG's `options.map` vs `options.generation` split: docs/architecture/configuration.md:80-99). |

**Boundary conditions the world should hand to a settlement frame** (derived from what FMG computes and what it lacks):
1. Datum and edge elevations: a DEM strip (or sampled profile) in metres along each frame edge, with the sea-level datum (FMG: h=20 ⇔ 0 m; frame edge heights come from `pack.cells.h`/grid h — no explicit edge contract exists in FMG).
2. Sea side(s): which frame edges touch ocean/lake water, with the water body's level (ocean 0 m; lake = spill height) and feature id/subtype (FMG `pack.features[].height`, subtype, `haven`/`harbor` per coastal cell: features-generator.ts:165-172, lakes.ts:12-16).
3. River entry/exit: for every river crossing the frame boundary, the crossing point, flow direction (in/out), discharge Q (m³/s; FMG `cells.fl` at the crossing), width (FMG only has mouth width — supply a per-vertex width), bed elevation and stage, upstream basin id (FMG `river.basin`), and whether it is navigable (FMG: flux ≥ 100: river-generator.ts:11).
4. Off-map drainage: FMG marks border exits with −1 and simply discards flux (river-generator.ts:246-250); the frame should receive the downstream head (sea level or next lake) so its priority-flood has a correct outlet elevation.
5. Rainfall and evaporation: annual precipitation (mm/yr) and temperature (°C) fields on the coarse climate raster, plus lake evaporation rate (FMG: `grid.cells.prec`, `grid.cells.temp`, lake `evaporation`).
6. Water table: none in FMG — define it in the world regime (see Lakes row).
7. Biome/vegetation class per cell and distance-to-coast/river fields (FMG `cells.biome`, `cells.t`).
