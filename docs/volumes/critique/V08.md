## 0 Verdict in plain words

Volume 8 is the most carefully engineered piece of plumbing in the set, and most of it should stay: the map lives in its
own frame on its own web address, SettlementForge stores the map beside the settlement and never inside it, the map works
out what changed by comparing the new record with the facts it already carries, it dates each change from
SettlementForge's own receipts, it never writes anything back, and every failure leaves the last good town on screen.

Four things must change before anyone builds it.

1. **Players would receive the Dungeon Master's whole file.** The volume loads the complete map file — and, for the
   "preview" path, the complete SettlementForge record with its secret seed — into every player's browser, then hides
   secret names only in the drawing. The design's own export rule says a host that keeps a place secret sends that
   person pictures, never the file, and SettlementForge's own player page is built so that it never holds the Dungeon
   Master's data at all. Players should get pictures of the map as the party knows it, refreshed when the map changes or
   the Dungeon Master reveals a place.
2. **The owner's newest underground rules do not reach SettlementForge maps.** The record's "ancient ruins" still become a
   mere surface decoration, and mines do not make caverns likelier. Nothing traces the cemeteries, where the catacombs
   now lie, or the cathedral, which always has the largest crypt, or the churches, whose number sets how many
   catacombs a city may hold. So the catacomb rules cannot be applied to any SettlementForge town.
3. **Every settlement that has lived through a single week would be refused.** The recogniser expects exactly the 41 or
   42 sections of a freshly generated record; a record after one week already has 42 to 47 (this lane counted them).
4. **SettlementForge's side cannot store what the map hands it.** The storage contract asks SettlementForge's small client
   to write encoded events and a fingerprint that only the map program can compute, and the messages do not carry them.

Beyond those, several owner rules of file g have their SettlementForge parts missing — the supply chains
SettlementForge itself lists, the institution ladders ("Blacksmiths (3-10)", "(guild)", "(district)"), threats that
come by sea for the waterfront wall, and the calamities the evolution volume expects the port to translate. Three
vocabularies are simply wrong against the real records (faction relations, history event types and condition states),
so those inputs would never fire. The rest are wiring, lifecycle and wording fixes.
