## 3 Calibration census, round 2

V12's lint (T-V12-20, PR tier from M1; V12 §3.11 l. 1818–1826) passes a calibratable compiled cell only with an
admissible provenance, an entry naming it or its column, or a `fixed:` note, and fails an entry whose "cell or column
exists and is calibratable and its metric exists" is not true. Round 1 wired the **writers** (V06's E1–E8, V02's four
exits, V11's C-exits). This round checks what those writers must write, and finds three gaps and two scope contradictions:

1. **The metric.** `CalibrationEntry.metric: MetricId` is required (V12 §2.6), and a `MetricId` is a V12 §3.4.2
   catalogue id. The confirming measurements the owning volumes state are their **bars** (T-V6-*, T-V2-*, and V12's own
   items 103–107 line, whose metric cell reads "the bars; the frame rows"), and a bar is no catalogue id: only a
   `NullModelSpec` result is (`siting.<spec>`); a `StatBarSpec` result and a hook bar are not. V06's `tables/evolution.json`
   columns (growth, walls, contract, plots, uses, fire, land, oxbow, silt, reclaim, raise, excavate …) have no catalogue
   metric at all; V02's `composition.json` columns only partly (`bldg.*`, `fm.*`, `tier.count`, `deck.buildings`). A seat
   landing E2 or M6a cannot write a lint-green entry without inventing a metric (SCC-56, SCC-57, SCC-58). V12's
   precedent J-V12.64 (three descriptive metrics added in round 1 for register lines "whose cells no metric read") is
   the pattern.
2. **The run kind.** V06's E7 "rate tuning … against the T-V6 bench metrics" is no admissible `CalibrationRun`: a
   `reference` run needs a reference baseline (no reference evolves a town), a `corpus` run waits for M-CAL, and a
   `fallback` run applies a register entry's pre-decided move (SCC-57).
3. **The fallback of a preset entry.** V02's SP-V2-3 pre-decides `hipInset` 0.5 for the `FM` entry when the reference run
   is rejected; V12 §2.5 and §3.7.2 (3) admit a `presets.FM` cell only in a `reference` run, so the `fallback` run that
   would apply it is refused (SCC-60).
4. **The writer of base cells a volume lands.** The base decline table's persistence rows `raised` and `retaining`
   (BCR-V6-26, STAGED M6-E) are registered on a line owned by V11 and written by V11's C3b seat at M3a, before the cells
   exist; V11 disclaims them and V06's exits register only `tables/evolution.json` (SCC-54, SCC-55).
5. **Scope, both ways.** V07's village range rows (`rules.ladders.ranges`) are "own, calibratable" while V12 §3.11 says
   the port's ranges for unnumbered qualifiers are never entries and V11 §3.12 never calibrates its town ranges
   (SCC-62). And a switch is calibratable with an entry at one table (`terrace.enabled`, V12 l. 1796) but "not
   calibratable" at another (`orientEnabled`, `splitEnabled`, V11 §3.7.4) (SCC-67, SCC-68).

The preset layer (the FM and VG entries) is the seam's other open joint: V11's source cell cannot hold the entries V12
writes and V02 and V11 assume, and the base change that would let it (file f item 376) scopes FM to `composition.json`
alone (SCC-51 – SCC-53).
