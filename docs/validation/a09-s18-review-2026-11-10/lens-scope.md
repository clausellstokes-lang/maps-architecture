## Findings

### SCOPE-1 (blocker) — 2A's CITY shadow derives nothing: in S18 nobody fills the store during S8, so line 6's bars are vacuous
- Draft: S18 LINE 1 REQ "In THIS round only the STATE READ (line 4) fills or serves the store; kerb() and readKerb serve the construction exactly as today"; LINE 4 REQ "THE SHADOW … after every served read … of a face whose state read would DERIVE … The shadow writes nothing, reads the store only"; LINE 3 "Where the parent's entry is missing or stale … the child reads by construction".
- Code: every read S8 makes goes through kerb() → readKerb (bentCutFabric.ts:653 kerbFace, :729 kerbSeed, :924 needle floor); nothing in layout calls a by-path state read (and cannot: package exports '.' only). A district cell is read by kerbFace (ladderOn :1359) and then cut (tryCandidate :838/:846) — it no longer stands when its child is read, so a missing parent entry can never be materialised later.
- Hence on the CITY probe (LINE 6) no child ever has a parent entry, no face "would derive", the shadow compares 0 faces: bar (i) "0 derivation defects" and bar (ii) "exact share ≥ 0.91 over the faces derived" are 0/0 — they cannot fail (J627's exact failure mode). LINE 7's NO-SHIFT bars pass trivially too.
- Change: LINE 4 — in the debug build, every served construction read with vertexContacts true KEEPS its result in the store as the face's entry (origin construction) — the store is beside the arena, so NO-SHIFT is untouched — and the shadow derives the children from those entries. LINE 6 gains a failing floor: faces derived ≥ the children S8 read whose parent S8 read (computed in the probe from the lineage log and printed), and the share is never computed over 0. LINE 1's "only the STATE READ fills the store" restated accordingly.

### SCOPE-2 (major) — the observer in splitFace cannot compute LINE 1's content key: it has no widths and no vertexContacts
- Draft: S18 LINE 2 REQ "`before` computes the parent's content key (line 1) while F stands; `after` records … for each child its content key after the cut"; LINE 1's key = vertexContacts flag + rings + edge spine keys + "per spine its half-widths sampled … and its declared ends".
- Code: splitFace(o, face, cut, opts) (faces/split.ts:171) and connectHole (:204) carry no SpineWidths; half-widths and ends come only from the reader's `widths` (kerb.ts:257-287 readSpine, `w.ends`; readKerb :2153 takes widths and vertexContacts). LINE 2's own evidence states "splitFace takes no widths". The lane's width lives only in layout's map (bentCutFabric.ts:832).
- Change: LINE 1 defines two keys — a width-free GEOMETRIC key (rings with the straight-through drop, edge spine keys, the through set of SCOPE-3) and the ENTRY key = geometric key + the reader's samples + flag; LINE 2's observer records geometric key → {parent geometric key, rows, side}; the derivation resolves the parent entry with the reader's widths at the child's read. Pin: a child read with a different width for the lane is not served the derivation for another width.

### SCOPE-3 (major) — LINE 1's content key misses construction inputs that S8's own writes change without touching F
- Draft: S18 LINE 1 REQ "any other write to F's boundary or to a bounding spine's width profile changes the key (986 (c)'s invalidation)"; the key = flag, F's rings, edge spine keys, per-spine samples at kept route vertices and declared ends.
- Code: the construction also reads (a) J318's vertex-only `through` spines — chains on edges LEAVING F's route vertices (kerb.ts:396-427, readFace), in the key nowhere; a lane of a neighbouring face (or district, across a seam) that ends at an existing vertex of F adds one with F's rings untouched; (b) each spine end's junction flag, computed from OTHER chains' edges at the end vertex (kerb.ts:303-324 junctionEnd): a crossroads continuation (bentCutFabric.ts:1093 continuationRefused admits it; junctionAt :1009-1017 reuses the junction) makes a second same-role lane end at an earlier lane's T, which flips the earlier lane's end from flat to capped ("An end where another chain of its role ends too is a CONTINUATION", kerb.ts:295-297) — the earlier lane's children keep their key; (c) the spine's whole own-level route (readSpine :257-287, routeLines over the chain; spineParts' round joins beyond F's corners, :550-607) — a vertex moved on a spine just past F's corner changes F's kerb, not F's key; (d) L2 content within attract reach (the read lays its parts at L2, kerb.ts dryLevel; closing.test.ts:3-5).
- Why: in 2A the shadow only compares DERIVED faces, so a stale kept/derived entry served for (a)-(c) is never seen; in 2B it is a silent wrong kerb on exactly the T / crossroads cases S8 makes.
- Change: LINE 1's key adds the through set (each vertex-only spine key with its junction flags at F's vertices), each spine's junction flags, and each spine's route vertices within its reach of F's box (or a hash of its run inside the clip window); (d) stated as out of the key with the reason (B-CLOSE / offRead, S19 line 1). New pins in LINE 1: (h) a lane in a neighbouring face ending at an existing vertex of F → F's entry not served; (i) a second lane ending at an earlier lane's T (continuation) → that lane's children not served. Mutant: the key without the through set → (h) red.

### SCOPE-4 (major) — the observer slot: L1 guard, rows and installation are unspecified or unsound
- Draft: S18 LINE 2 REQ "`before(t, face, faceLevel)` … `after(token, children, rows)` … The kerb state's module installs its observer when it is evaluated (the stage always imports kerb)"; session clause "null until the kerb state's module installs its observer when it is evaluated".

Delete "when it is evaluated" from LINE 2 and the session clause. Pin: a splitFace on an L2 face and one with faceLevel 3 record no lineage and no failure.
