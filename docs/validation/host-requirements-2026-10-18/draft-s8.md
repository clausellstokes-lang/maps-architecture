## Everything else worth knowing

The one decision the owner makes next is when the host's track runs and whether replacing the realm map counts as post-launch work (V13 Q2; docs/volumes/V13-world.md §11 Q2 (line 4273)). The one risk that matters most is the host's map itself: it is a built copy of the generator, rebuilt from source that is not in the repository, with no integrity pin, and the host's own upgrade step would break it (research/fmg/notes/sf-host-fmg-integration-audit.md §2.5 (lines 78–80)). Freeze that copy now and do not upgrade it until the port lands.

Three words recur below. The "port" is the one-way channel that carries world facts from the map to the host. The "canon" is the host's frozen record of a world; to "canonize" is to freeze it. A "lens" is a dated map overlay, such as plague spread or patrols.

### Sequencing

Each step pairs a map milestone with the host batch that rides on it. The gate is what must be true before the host batch starts.

1. **Now, before the host launches: H1–H3.** On its current copy of the generator, the host stamps its map capture with frame, seed, scale and unit, adds an export command, runs a per-map census of travel-time bands, and adds its calibration rows. Map side, this is the M0 gate. Gate: the brief's bar T (18). The band census also ends the travel-distance deferral (see RK-05). Source: docs/OWNER-BRIEF-WORLD-SITES-HYDROLOGY-DRAFT-2026-10-16.md §9 (lines 199, 206); docs/volumes/V13-world.md §11 Q2 (line 4273).
2. **With the first world milestone (M-W1): H4–H11.** M-W1 delivers terrain, water, climate, biomes, siting, the charter and the port. The host builds its side of the port and a second builder for its spatial digest, the frozen integer summary of territories, gates and distances. Source: docs/OWNER-BRIEF-WORLD-SITES-HYDROLOGY-DRAFT-2026-10-16.md §9 (lines 205–206); docs/volumes/V13-world.md §11 Q4 (line 4296).
3. **Also with M-W1 and M-W2: the kernel's random-source rows, including patrols.** The map engine's core keeps append-only lists of named random sources and stages. ### What the FMG audit found in the host's fork

The audit read the host's copy of the Fantasy Map Generator (FMG) and how SettlementForge drives it. Its file is research/fmg/notes/sf-host-fmg-integration-audit.md; section and line follow each item.

- The host's map is a built copy of FMG version 1.114.2 from April 2026 (upstream commit bb5039d7, host revision `sfdrop16`). It predates the minimap, the fill brush, eroded terrain and the economy layer. §1 (line 10), §2.1 (line 20).
- Inside the host the generator makes geography only; states, towns, religions and provinces are zeroed. So today nothing political comes from the map, and the host's political facts (H12–H17) are the only source. §2.4 (lines 72, 75).
- The host never reads the map file. It stores the file as opaque text (about 100 KB to 1 MB), a seed, and placement rows in the generator's pixel space. Old worlds can only be re-read by the adapter or the fork. §1 (line 10), §3.4 (line 130).
- Today's canon is a one-time copy of nine arrays, frozen into an integer digest, premium-only, for generated maps only, capped at 400,000 bytes, with no cell coordinates kept. H5's second builder replaces exactly this. §3.2 (line 96), §4.2 (lines 149–151).
- That copy leaves out lake-versus-ocean ids, distance to coast, harbour and border cells, river and lake entities, map size and the distance scale. The capture's frame fields come back empty every time, because the generator never sends them. H1's stamps close part of this gap. §3.4 (line 132).
- Because of those gaps the host guesses lake versus ocean by a bounding box, cannot call a lake salt, and routes sea lanes by a height rule. Native water classes and real rivers through the port fix this. §4.2 (line 152).
- No settlement input comes from the map. Terrain, coast, river, trade access and threat are chosen from settings or random pools, and any later disagreement with the map is recorded, never reconciled: "genesis is sacred". This is why the map bends to the dossier. §6 (lines 221, 224).
- The map bundle was rebuilt from modified source that is not in the repository (it exports `Settlements` instead of `Burgs`, with 28 dependent call sites), has no hash pin, and its main script is outside every check. A known upstream lake bug is kept on purpose so the same seed keeps giving the same map. §2.3 (line 37), §2.5 (lines 78–81).
- Terrain edits are under-reported: the "terrain changed" signal fires when a tool opens, not when terrain changes, and double-click edits are not reported at all. Native edits go through the decree law with fingerprinted outputs. §3.2 (line 112), §7.3 (line 261).
- Roads are routed inside the map frame by a path search capped at 25,000 steps, order-dependent, and never saved. The host's own design calls this "in the wrong layer". On native worlds the map computes and saves routes (W7); the host should consume them. §3.2 (line 105), §4.8 (line 180), §7.3 (line 256).
- The scale is 3 km per pixel by default, set once at first canonize. Mode speeds are foot 150, cart 110, river 280, coastal 450 and sea 900 km per week; without a datum, travel falls back to about one week per hop. This is the normalized arm native worlds ride until H2. §4.2 (line 154), §7.2 (line 251).
- Town and annotation ids are minted from the clock and random numbers; they are interface state and must not leak into the canon or share codes. Four map events have no host listener. The generator's own SVG, PNG and GeoJSON exporters are not connected, and the map frame is mounted without a sandbox. §4.1 (line 141), §3.3 (line 127), §4.9 (lines 183–184).
- The host's town map has no link to the realm map ("no FMG iframe, no bridge"); it draws its river and coast from the dossier. So door 1 staying closed matches the host's own design. §4.10 (line 189).
- No host document plans to replace the generator; the host calls the fork an open structural risk ("either commit to hard-fork or upstream the bridge hooks"). Two host design records are missing from the clone: `DESIGN_FMG_WEAVE` and the owner decision queue, which lives on a ledger branch. §5 (lines 204–206, 214).
- Six host facts the new world must treat as canon: the frozen digest and its version; placements and the move-lock; the frozen settlement settings; share codes and instant-world plan law 1; the port, river and coast contract; the `kmScale` datum and mode speeds. §7.2 (lines 246–251).
- What the host must send: a per-campaign map charter beside the seed (frame size, datum, which edges are sea, elevation range) and river requirements per settlement. What it must receive: a one-way derived-facts channel returning each settlement's cell, coast, river and port truth, biome, climate band and elevation, plus territory, gates and distances, versioned like the digest. The host must also emit or re-version the generator's biome ids 0–12 and 0–255 rainfall scale, and make the instant-world box the real frame. §7.3 (lines 254–262).
- Eight questions only the host developer can settle: where the modified source lives; what the two missing records say; the real production map size; whether any instant world has ever canonized; whether gallery import of map blobs still works and how blobs migrate; what `cells.g` means on older packs; whether any `.map` was saved under a version other than 1.114.2; where the town-map 3D viewer lives. Several gate H1 and H18–H20. §7.4 (lines 265–271).
