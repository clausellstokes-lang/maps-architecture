# Encounter maps and world sites — what the host (SettlementForge) supplies, lacks, and the FP laws that bind

**What "FP" means, in plain words.** "FP" (short for "Foreign Policy") is SettlementForge's own name for its campaign simulation: thirteen chartered programs — trade, populations, war, travel, spying and others — that run a realm's settlements week by week on top of an older war-and-peace engine and a spatial engine (research/sf/fp-simulator.md §0 (line 32)). For the map, the key fact is that FP reads the world's geography as a record captured once and never changes it; everything the campaign adds is kept in side records (research/sf/fp-simulator.md §0 (line 40)).

**How to read this.** Each row says the plain fact first, then the exact pointer (file, section, host name) for the host developer. A *ledger row* (D1, T2, …) is one row of the physical-quantity ledger in research/sf/fp-physical-integration.md §2, with its verdict from §8. **The ledger's verdicts look the other way round from this file's headings:** SUPPLIED / PARTLY / MISSING / NONE-OWED say what the *map's world port* gives the *host*. They are sorted here by where the work falls: NONE-OWED rows (the host derives them itself) and MISSING rows the host already has today sit under "host supplies"; PARTLY rows under "host partly supplies"; SUPPLIED rows that leave the host a conversion to do, and MISSING rows nobody has, under "host lacks"; plain SUPPLIED rows under "map-side only". All 80 ledger rows appear exactly once (row A1 is shown as PARTLY, per the ledger's dated note of 2026-10-17). Both research notes are marked "pending Fable review" by their authors, to be re-checked (fp-physical-integration.md line 3; fp-simulator.md line 3).

## Other things worth knowing (noticed while reading)

1. **Two names for one host record.** V14 §1b.5 calls the host's site record `WorldSiteRecord` (docs/volumes/V14-sites.md §1b.5 (line 456)); owner question Q2 says its shape is V14 §2.2's `WorldSiteHost` (§11 (line 3068)). The host developer should treat them as the same ask until V14 settles the name.
2. **The ledger's own counts disagree.** The summary paragraph says 62 rows (34 / 16 / 12); the assembler's note counts 80 rows (30 SUPPLIED, 17 PARTLY, 7 MISSING, 26 NONE-OWED) and keeps the paragraph for re-checking (research/sf/fp-physical-integration.md §1 (lines 23–25)). This file follows the 80-row count; with the dated note moving A1 to PARTLY it reads 29 / 18 / 7 / 26.
3. **Part of the world-port surface the ledger read is retired.** `seats(world, seeds)` and `TerritorySeed` no longer exist; the host's territory is now the seat territory (W8a) and gates are answered by the canon's crossings (research/sf/fp-physical-integration.md §8 (lines 458–468)). Rows D1 and A1's wording is historical.
4. **Where the scale comes from is said two ways.** fp-simulator §8 item 1 says the map must export its distance scale and unit at canonisation (OD-FC-22) (research/sf/fp-simulator.md §8 (line 1078)); the ledger's §8 row D3 says the map's declared centimetre unit replaces that exported-scale read (research/sf/fp-physical-integration.md §8 (line 379)). Same end, different mechanism; worth one ruling.
5. **Line of sight exists only on the map side, and only for tabletop exports.** The encounter crop's VTT export writes sight-blocking lines from the map's walls and items (docs/volumes/V14-sites.md §5.3 (line 2530)), while the host has no line of sight anywhere (ledger L1). Those lines must never be offered as a host fact.
6. **Patrols.** Nothing in this source family gives the host a patrol mechanic. The only statements are: the patrol cadence is an owner-ruled map picture that reaches the host as an offer; patrols lowering danger is refused because the host does not apply it (research/sf/lens-implications.md §4.3 (lines 445–449)); danger is the host's embattlement (ledger A6); the host's territory is W8a, never the sway (ledger §8 bracket). If the owner wants patrols to change danger in the simulation, that is a new host rule to ask for — it is not in these sources.
7. **Timing of every host ask.** Nothing on the host side is scheduled: the owner's standing order (UI and prose release first; the EC gate) still binds (research/sf/fp-simulator.md §0 (line 49)). V14 is written so the map works with every site map-tier until the host record lands (docs/volumes/V14-sites.md §1b.5 (line 452)).
8. **V08 is a map volume.** Where V14 says "V08 §3.14's reveal" or "V08 adds DR-V14-1", V08 is the map's own host-adapter volume; the actual host capability is the record and events in owner question Q2 (docs/volumes/V14-sites.md §11 (line 3068)).
