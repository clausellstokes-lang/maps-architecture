### VAH-r6-01 — major · MATRIX-GAP · owner V08

**Claim.** Round 6 (R6-10, VAT-r5-02) gave a public note in a picture its form. §11.2's `ExportOpts.pins` (base l.
16323–16329) says: "each public note a numbered marker at its thing's anchor … numbered from 1 … the numbers keyed on
§9.5's separate legend sheet to the pin's label and note and to the public note's text; a public note on a thing the
export's knowledge withholds left out". §9.5 (l. 15168–15169) adds the public notes to its *Annotation layer*
("numbered markers and a separate legend sheet"), and the canon's round-6 ruling says the same. So the note's words now
reach a picture only on the legend sheet.

V08's players' view still promises the players the notes:
* V08 §3.14 (2) (l. 2299–2301): "Every picture is drawn with … the document's public notes, view pins and annotation
  layer (§2.9 view state, §9.5)".
* §5.3's *Notes and pins in pictures* (l. 3110–3113): "the players see the public ones in their pictures".
* T-V8-41 (l. 3308): "public notes and view pins are drawn, private ones never".

The set has no carrier for the sheet. `PartyPictureSet` (l. 377–383) holds `levels` (the PNG tiles), `svg` and
`gazetteer`, and `drawDigest` hashes those alone. `putPartyPictures` stores only that. The player's viewer (§3.14 (4),
l. 2319–2322) shows the tiles and a caption. The party gazetteer holds places, not notes. A player therefore gets
numbered markers with no text.

Two builders differ. One invents a legend member the record, the digest and the viewer lack. One draws the note text on
the tiles, against §11.2. One leaves the notes out, against V08 §5.3 and T-V8-41.

§5.3's bullet also says every picture draws the notes, while §11.2 draws them "never in a picture unless asked"
(`pins` default false). It does not say that a party render always asks.

The subject is shared by rendering (§9.5, §11.2), V08 (the party set and `exportPicture`) and V09 (the Picture tab's
"pins and public notes"). The agreement matrix has no row for it.

**Required change.** V08.
1. `PartyPictureSet` (l. 381), after `gazetteer: Uint8Array /* … */;`, add: `legend: Uint8Array /* §9.5's legend sheet
   of the set's annotation layer — each numbered view pin's label and note and each numbered public note's text, numbered
   as §11.2's ExportOpts.pins numbers the markers on the tiles and the SVG — under the party key, an SVG inert by §11.1's
   bar; an empty sheet when the set draws no marker */;`. In `drawDigest`'s comment, change "the gazetteer's bytes and
   `week`" to "the gazetteer's and the legend's bytes and `week`".
2. §3.14 (2), the closing clause: "the document's public notes, view pins and annotation layer (§2.9 view state, §9.5)
   and never a private note or a DM-only pin." → "the document's view pins and public notes as §9.5's annotation layer —
   every party render passes `ExportOpts.pins` true, so each is a numbered marker on the tiles and the SVG, a note on a
   place the party key withholds left out (§11.2's `ExportOpts.pins`), keyed on the set's legend sheet (`legend`, drawn
   by the same render) — and never a private note or a DM-only pin."
3. §3.14 (4): after "the caption `host.party.asOf` (the set's `week`; V08 §5.1's table)", add ", the set's legend sheet
   (`legend`) below the tiles when it keys any marker".
4. §5.3's *Notes and pins in pictures*: "A picture draws the document's public notes and view pins and the annotation
   layer (§2.9 view state, §9.5) under its key;" → "A picture draws the document's view pins and public notes as §9.5's
   annotation layer — numbered markers keyed on its legend sheet — when its `ExportOpts.pins` asks (§11.2; every party
   render asks, V08 §3.14 (2)), under its key, a note on a thing the key withholds left out;".
5. T-V8-41: "public notes and view pins are drawn, private ones never" → "public notes and view pins are drawn as
   numbered markers keyed on the set's legend sheet (`legend`), a public note on a place the party key withholds left
   out, private ones never".

This is one fix with VAH-r6-02.

pixel diff cannot pass as written.

define. One runs the diff only on a fixture with no pin or note. Before round 6, §11.2 drew pins "as the view draws
them", so the frame and the set could agree.

**Required change.** V08.
1. §3.14 (5): "So the DM sees in the live frame exactly what the next party set will show;" → "So the DM sees in the
   live frame exactly what the next party set will show but its annotation layer — the view pins and public notes the

   the fixed sun)" → "the frame's city band equals the party set's z0 picture at the same head (a pixel diff, both drawn
   with the fixed sun, on the fixture's copy holding no view pin and no public note — the set's numbered markers being
