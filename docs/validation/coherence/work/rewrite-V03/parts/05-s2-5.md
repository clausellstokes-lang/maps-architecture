### 2.5 Lifecycle of every new state field

Each piece's readers are V03 §1b's; the plan edits' own rows (the events, New random, `setAttr(basement)`'s
consequences) are V03 §4.1's edit table.

| field or record | create | persist | regenerate | undo | migrate |
|---|---|---|---|---|---|
| `Storey.furniture`, `FurnitureItem`, `Room.nextFurniture` | F1–F4 in the plan derivation; `instance` add on a stored plan | in the elaboration chunk (unstored); in the stored composition's plan once any plan event or `instance` stores it (§2.6) | re-derived with the plan (`plan.furnish`); a stored plan's items kept by id; after a carry each is checked and re-snapped or orphaned (V03 §4.3); New random on `plan.furnish` re-places every item not `edited` (V03 §4.3) | the event's undo record keeps the former storey (§7.4's plan-event row) | a document before file f item 232 has none: the first derivation fills them; a stored plan without the member gets an empty list and F1–F4 on its next re-cut; a quarter-turn `rotCdeg` of a draft reads as the wing frame's angle plus the quarter turn |
| `FurnitureItem.edited` | `instance` add, move or restyle | with the stored plan | kept | with the storey | absent: not edited |
| `Room.name` | `setAttr plan/rooms/<id>/name` (V03 §4.2) | with the stored plan (the edit stores it) | kept by the room's re-match (V03 §2.2); a room re-cut away takes its name to the kept room that re-matches it, else the name is orphaned and reported | `setAttr`'s inverse | absent: the role's display text |

| `Building.declaredRooms` | `setAttr declaredRooms` (V03 §4.2) | the building record (§2.6), in its leaf digest | an edited attribute (§7.2): kept by every re-derivation and re-cut | `setAttr`'s inverse | absent: none |

**The derived pieces** (V03 §1b's list) are never stored; each is recomputed at its read, and a change of its inputs
reaches the plan as follows (undo: its inputs' undo; migrate: none, nothing being stored — the stair-entered reading
ships with the crypt derivation at M6-U, so no shipped document holds a crypt without it):

| derived piece | what moves it, and what that does to a plan |
|---|---|
| the level reading, storey heights, `floorCm` (V03 §3.3); the roof terraces `T(x)` and their walkability (V03 §3.4a) | re-derived with the plan; a stored plan re-derives the terraces at read from its wings and openings |
| the crypt's capped bays (V03 §3.7.4 (3)) | every rank run: re-grown away when the crypt re-grows; their `undercroft` room persists with a stored plan, re-matched as any room; the causing event's undo restores `Basement` |
| the stair-entered reading (V03 §3.7.4) | a wing change (a `setMassing` commit, a designation mutation) or a change of the crypt's step-2 or edited ring moves it — never a rank event, which moves no vault — and the basement is re-derived with it inside the causing event (the `Basement.crypt` row above), which marks the plan stale or re-cuts a stored one; the extent it chose persists as `Basement.ring` |
| the outside ground per wall and the outside digest (V03 §3.6 W2) | a `RetainingWall`, a terrain change, a levelled platform's datum (the values `levelledGroundCm` returns, BCR-V5-30) or a deck change beside the building moves the digest (held in `ElaborationRecord.inputs`, §2.8, non-canonical): an unstored plan goes stale, a stored plan is re-cut inside the changing event (V03 §4.3; §7.3) |
| `basementDoor(b)` (V03 §3.7.1) | a `RetainingWall`, terrain, levelled-platform, wing, entrance or basement change (from M6-U `Basement.crypt` among the basement's fields, its vault never moved by the rank) moves it, which marks an unstored plan stale and re-cuts a stored one inside the event (the outside digest, the basement's change; §7.3) |
| `stackAccessDoor(b, a)` (V03 §3.7.2 (1)) | a wing, stack, stair or access change moves it, which marks an unstored plan stale and re-anchors a stored one's head inside the event (§2.8; V03 §4.3); the head's `door` persists with a stored plan |
| a split half's programme (`programmeSource.half`) | a split or a merge back onto one plot changes `Use.branchOf` (in the leaf digest), which marks both buildings' plans stale and re-cuts stored ones (§2.8, §7.3); the causing event's undo restores both uses and both plans |
