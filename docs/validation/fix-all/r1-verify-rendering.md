# Fix-all round 1 — verification of the RENDERING area (lane fixall/verify-rendering-r1)
> PENDING FABLE REVIEW — Opus-produced (fixall/verify-rendering-r1), not yet checked by a Fable seat; queued in docs/FABLE-REVIEW-QUEUE.md.

Status: COMPLETE (2026-09-25).

**In plain words.** The rendering area (drawing, labels, exports, speed budgets) said it had fixed 64 problems. This
check read the whole revised architecture and tested each claimed fix against the problem it was meant to solve. 61 of
the 64 hold: the architecture now contains a real mechanism for each. Three are not finished — in each case a sentence
elsewhere in the document still says the old, wrong thing, or one small piece the problem asked for is missing. The
check also found problems the revision itself introduced: five serious ones (label colours that cannot meet their own
contrast rule, a speed promise that is only true at one population per size, a replay rule that can rename streets,
work handed to a background thread that cannot see the town, and tile-upload limits that contradict the first-map
times) and a list of smaller ones. None of the fixes uses deferral language.

## 1. Scope and method

* **Read in full:** `docs/ARCHITECTURE.md` (6 350 lines, every section), the 64 item records in
  `docs/validation/fix-all/index.json`, their round-1 rows in `docs/ARCHITECTURE-VALIDATION.md` §R1.1, the integration
  log `docs/validation/fix-all/r1-integration-log.md`, and the rendering draft's cross-area request tables
  (`docs/validation/fix-all/r1-rendering.md` §3).
* **Checked against evidence (executed):** the contrast matrix and role chromas of §8.2 recomputed from the sRGB table
  with our own CIEDE2000 implementation (`docs/validation/bench/fixall_verify_rendering_contrast.py`, output `fixall_verify_rendering_contrast.out`); the MFCG matched sizes,
  building counts, walled areas and timings of §12.2 against `captures/mfcg/exports-sweep-2026-09-25/README.md`; the
  options behind the 13 349–36 480-building size-80 cities against `research/findings/profile-mfcg.md` §7.1 and §10;
  the reference machine against `captures/mfcg/2026-09-21T11-25-32/meta.json`; every `§n.m` pointer in §8, §9, §11 and
  §12 (0 dangling, scripted); §12.3–§12.5 arithmetic (per-building rates, ratios, the 245 ms critical path, first-map sums).
* **Verdict rule (the owner's no-defer rule).** ACCEPTED only when the architecture now contains a concrete mechanism
  that defeats the item's failure scenario (the quoted sentence is the evidence). UNRESOLVED when the mechanism is
  missing or partial, or when a sentence elsewhere in the document still states the failure the item named. Problems the
  revision introduced that are not one of the 64 items are §3's new findings, each with an owning area.
