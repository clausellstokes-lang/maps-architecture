## 0. In plain words

All eight things round 3 set out to fix in the drawing, labelling, export and speed sections are fixed in the text:
towns made from different seeds no longer share tree patterns and roof colours; the speed of building the town (not
only of drawing it) is now stated honestly for every size, with the slower large sizes put to the owner for a veto;
style files can say where street outlines go and are refused when they are ambiguous; the compass, title, legend and
ruler get their answers from the background drawing thread within one screen refresh; SVG exports have a stated home
and their memory is counted; the ready-made tree patterns are the same on every computer; and the 3-D city export
declares its one extra field. Every number behind these was re-computed and agrees, nothing is put off, and none of
the earlier fixes broke. Checking the new text turned up seven new small problems, all in this area: (1) the rule that
decides at the first milestone whether to use several background workers or one compares against a flat 0.3 s, although
the speed rule itself predicts up to 0.34 s for an ordinary city — it would switch to the slower setup for no reason;
(2) the drawing interface as written cannot pause a tile half-way, which the new "answer within one frame" rule needs;
(3) two labels the user pinned can end up on top of each other after the map is warped, a street is renamed or the font
changes; (4) the new "no town more than a quarter slower than its rule" check is run on thousands of towns timed side by
side on a shared test machine, so one hiccup could fail the nightly check or loosen the promise for good; (5) one
per-building speed figure is off by one millionth of a second; (6) a large print export now runs in the same background
thread as the map tiles, with no rule saying the map you are looking at comes first; (7) the tree-pattern library has no
time budget and is built the first time you zoom in — it can be computed once when the product is built and shipped as
data.
