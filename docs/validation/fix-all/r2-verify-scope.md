## 0. In plain words

This seat re-checked the parts of the design that say what is built and in what order, how it is tested, how it stays
legally clean and which decisions were taken, after the second fix-all round was merged into `docs/ARCHITECTURE.md`.
**All fourteen problems assigned to this area in round 2 are now fixed by a concrete mechanism in the text**, including
the two serious ones. The test of "does re-rolling an area give the same kind of result as a fresh town" is now a
calibrated rank test; rebuilt here from the design's own words, a perfect re-roller fails it only about one time in a
hundred, as intended. And a milestone whose side-by-side panel the owner has not rated keeps building but is marked
*provisional* and can never claim "at parity", "mastered" or the stage-2 gate without the owner's eye. The borrowed
FTG add-on names are gone (checked: none of them appears anywhere in the document). The 37 items this area had already
fixed in round 1 all still hold.

The check found **nine new small problems** that the round-2 rewrite introduced; none is serious and none is a
deferral. One row of the build plan was broken across four lines at the merge, so the table displays it wrongly. The
plan now says the metropolis size is "built" only at the M2b milestone, while the tests from M1 already generate
metropolises. One parity row still promises "under a second at every size", which round 2 openly withdrew for the very
largest cities. The check that label placement is identical in every browser covers the label code but not the drawing
code that feeds it. Two record formats disagree on small details, and the formula that picks the owner's panel seeds is
not spelled out exactly. One pointer names the wrong section of the merge record. The rule that scans this document
for copied reference material cannot run as written until the first milestone builds its word list. And the re-roll
test's "catches 99.5 % of faults" figure assumed its four measurements are unrelated; with realistic, related
measurements it catches 92–95 % per night, and doubling the nightly sample (about 12 CPU-minutes) restores 99.7 %.
Each finding carries its exact change. No deferral wording remains in this area's sections.
