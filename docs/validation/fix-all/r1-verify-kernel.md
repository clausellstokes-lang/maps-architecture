# Fix-all round 1 — kernel verification (lane fixall/verify-kernel-r1)
> PENDING FABLE REVIEW — Opus-produced (fixall/verify-kernel-r1), not yet checked by a Fable seat; queued in docs/FABLE-REVIEW-QUEUE.md.

Status: COMPLETE (2026-09-25).

**In plain words.** The kernel is the part of the design that does the shape mathematics. After round 1 it is much
stronger: the five drawing levels now live in one shared store, shapes are referred to by name instead of by fragile
slot numbers, the boolean engine and the roof skeleton are decided with tests and fallbacks, and the spatial index no
longer rebuilds itself after every small change. Of the 21 kernel items, 18 are genuinely fixed. Three are not quite:
the "attraction" rule that snaps new lines onto old ones still has a gap that can create a too-short edge (shown by a
counter-example and a simulation), positions stored in the edit log and in some records can still bind to the wrong
corner after an upgrade or a warp, and the warp tool can still shorten an edge below the minimum without anything
noticing. Hunting for new problems found 19 more, seven of them serious: the town walls' bands are built before the
streets that would erase them, per-vertex street widths are stored by position in a list that the kernel reshuffles,
the parallel-worker merge the pipeline relies on is not specified in the kernel, the boolean acceptance test contradicts
the snapping rule, two budgets for the same step disagree, the "canonical order" rule cannot apply to steps that depend
on each other, and warping near a coast does nothing. Each has a concrete required change below; none is deferred.
