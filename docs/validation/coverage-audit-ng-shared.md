## 1. Legend and method

**Tier** (owner product scope, 2026-09-25). **BASE** = an MFCG/FTG-class capability the stage-1 town/city generator must
cover at parity (parity is the floor; an original technique that replaces the reference technique counts). **STAGE-2** =
an NG-class capability the district→neighbourhood interface must be ready for (the check is that the base's model,
interfaces and display list can carry it, not that it is built). **VILLAGE-LATER** = a VG-class capability; the only
check is that the base does not preclude it. Watabou's shared library (geometry kernel, palette, hatching, shadows, trees,
naming) is recorded in this slice mostly through NG and the 2017 source; such rows take the tier of the product whose
capability they are *in this slice's evidence*, and are marked `(shared)` where the same capability also exists in
another reference. The **leading tier word is the one judged** (and counted in §3); the NG-measured laws of the bent cut
(N16–N20) and the lot side-wall rule (N23) are tiered BASE because the architecture adopts them as the base's infill. Rows that describe other watabou toys (dungeons, Perilous Shores, cave, Toy Town…) are
**OUT** (no tier: not MFCG, FTG, NG or VG) and are kept only where a technique is plausibly reusable; they are not
coverage requirements.

**Coverage.** `COVERED` (cite ARCHITECTURE.md §) — specified to a depth a builder can implement without inventing the
capability; `PARTIAL` — present but a named part is missing or left unspecified; `MISSING` — no section provides it.
VILLAGE-LATER rows: `NOT-PRECLUDED` / `PRECLUDED` (with why). For STAGE-2 rows COVERED means the base model and the
neighbourhood-generator interface already carry what the capability needs.

**Sev** (PARTIAL/MISSING only). `H` = a parity-floor gap in a user-visible BASE capability, or a model gap that would block
stage 2; `M` = a secondary capability or a rule/parameter the builder would have to invent; `L` = cosmetic, an editor
nicety, or a reference detail whose absence is defensible.

**Evidence tags.** `ST` stated by the creator; `SH` shown in our recordings or captured data; `IN` inferred by a reader;
`NO` named only; `CR` critic ruling or addendum; `src` read in the 2017 source by a reader (verified by `_critic-os.md`
where noted).
