## II.3 Block content dispatch, pins, local identities (S2 context features)

A stage-2 table maps `(block area, spacing to the nearest green, spacing to the nearest landmark or manor block, district
kind, prosperity band)` → the weighted choice NG makes among Normal / Manor / Empty / Green (CONFIDENCE B6: NG's
`createGreen` on 23–58 % of Normal blocks with no target is the failure — ours has a target per band, from §4.9's rules); a
**minimum landmark spacing** row keeps landmark and manor blocks apart (NG's "kept apart from each other"; COV-NG-XA07).
**Pins** of the neighbourhood tier (wells, fountains, large trees, statues, monuments, bandstands) are placed in yards and
squares by a probability gate per kind and band, as refine-mode presentation detail; the base's own pins (§4.7 S11) are model
entities and appear at every LOD. **Local street identities** (names, surfaces, widths) come from the way records and the
naming grammar; context features (stage-2 feature S2: quays, the intervallum along the wall, stepped streets, bridge
approaches) are constraints available inside the boundary. A manor compound's enclosure wall and gate are the base's
`PlotBound` treatments (§2.5, §4.7 S11), so the close-up draws NG's walled compound from model data (COV-NG-N27).
